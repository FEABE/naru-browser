# Naru 독립 브라우저 완성 계획

기준일: 2026-10-11. 개발 목표는 **Naru를 먼저 완성하고 Aside와 ego lite의 장점을 결합하는 것**이다. 완성한 Naru 화면과 기능을 Preseller에 내장하는 순서는 유지한다. 사용자는 Aside의 장점 중 **세로 탭·검색·북마크 등 일상 브라우저 사용성을 우선**하도록 선택했다.

## 참고 근거와 적용 방향

2026-10-11에 ego-browser의 작업 공간 6에서 공식 사이트를 열어 확인했다. 아래 제품 설명과 시연 화면은 참고 근거이며 실제 제품 성능을 독립 검증한 결과는 아니다. 벤치마크 순위, 비용 절감이나 보안 관련 홍보 문구를 Naru의 달성 기준이나 보장으로 가져오지 않는다.

| 참고 | 확인한 점 | Naru에 적용할 방향 |
| --- | --- | --- |
| [Aside 공식 화면](https://aside.com/) | 세로 탭, 북마크, 주소·검색 입력, 작업 현황을 한 화면에 배치한 시연 | 일상 탐색을 쉽게 하는 탐색 구조, 명확한 선택·상태, 간결한 화면 |
| [Aside 브라우저 에이전트 소개](https://aside.com/features/browser-agent) | 로그인된 웹사이트와 탭·파일을 연결한 작업 흐름 소개 | 브라우저 기본 기능과 작업 결과가 끊기지 않는 사용 흐름 |
| [ego lite 공식 소개](https://lite.ego.app/) | 사용자의 탐색을 방해하지 않는 작업 공간, 외부 에이전트 연결, 로그인 상태를 사용하는 브라우저 제어 | 사용자·AI 공간 분리, CLI, 명확한 제어권과 사용자 개입 |

Aside의 공식 시연 화면은 `artifacts/aside-reference-2026-10-11.png`에 있다. 앱 자체에서 북마크·모델 연결 등을 실행한 증거는 아니다. ego lite의 공간 화면은 사용자가 제공한 이전 이미지와 기존 로컬 검토도 참고했지만, Naru의 구현 증거와 구분한다.

이후 사용자가 Aside를 설치해 두 앱을 Computer Use로 비교했다. [실제 앱 비교 기록](browser-comparison-2026-10-11.md)에 새 탭·북마크·검색·AI 페이지 제어와 중지의 실행 결과를 분리해 남겼다. Aside의 Bookmarks/Chats/Tabs 사이드바와 통합 검색을 일상 사용성의 참고로 삼고, ego lite의 별도 작업 공간·제어권 표시·CLI를 유지한다. Aside의 내장 대화 전체를 지금 복제하는 범위로 확대하지 않는다. 메모리 우열은 조건을 맞춰 측정하지 않아 판단하지 않았다.

이 표는 현재 합의한 우선순위와 남은 작업을 추적한다. 첫 두 항목을 완료해도 전체 목표를 완료로 표시하지 않는다. 실제 대상 사이트의 대표 시나리오, 일상 사용과 장시간 자원 회수까지 확인해야 독립 브라우저 완성을 판단할 수 있다. 배포는 현재 요청 범위에서 실행하지 않으며 개발 검증과 서명·공증 준비를 구분한다.

아래는 이전 포커스 수정 v3의 검증 기록이다. SHA-256 `93bbf74352f3565713a24b4c9b20729e2b7bb627f8b771c7f91f35ebb9b9a9bd`다. `artifacts/search-preview-v3-rust-tests.log`의 Rust 128개, 전체 타깃 Cargo 검사와 release 빌드가 통과했다. 초기 sandbox의 소켓 생성 3개 실패는 별도 로그에 보존하고 권한을 받아 같은 검사를 재실행했다. 이전 v2 앱은 exit 0으로 종료했고 v3 빌드에서 중간 파일 4,332개, 2.4GiB를 정리했다.

v3의 빈 탭 네이티브 회귀에서 기억된 현재 탭을 CLI로 닫은 뒤에도 통합 검색과 북마크 목록의 입력 포커스를 유지하고 추가 붙여넣기를 받아들였다. 최초 HTTP 탐색은 키체인 승인 전 `WAIT_TIMEOUT`이었지만, 사용자가 항상 허용한 뒤 재빌드 없이 같은 탭의 실제 URL과 문서 complete를 확인했다. 로드된 사용자 탭을 닫은 뒤에도 통합 검색 입력이 이어졌고, 북마크 검색 결과를 Enter로 열면 새 사용자 탭을 만들면서 AI 작업의 active/revision 1과 선택 탭을 보존했다. 북마크 이름 편집 중 원본 탭을 닫아도 입력 포커스와 고정 URL이 유지됐으며 변경한 이름이 같은 id와 URL로 저장됐다. 검증 북마크와 작업은 정리했다. 한글 붙여넣기 검증이며 IME 조합 검증은 아니다. v3의 로컬 CEF 작업 6개·공간 10개·단일 창 6개, 총 22개도 통과했다. 검사 작업 7개는 모두 종료했고 기존 빈 사용자 탭 1과 대기·캡처·생성 예약 0을 확인했다. 이어 정상 종료 exit 0과 같은 바이너리 재실행의 빈 탭·빈 북마크 목록을 확인했다. 근거는 `artifacts/search-preview-v3-suite.json`, `artifacts/search-preview-v3-suite-state.json`, `artifacts/search-preview-v3-validation.json`이다. 근거는 `artifacts/search-preview-v3-native.json`이다.

이전 v2(`f9168ced388db274d3d18538a792081c7b5302bffc6b7817b4a59616c9227f74`)에서는 탭과 북마크가 같은 숫자 ID여도 구분되고, 방향키와 마우스로 기존 사용자 탭 재사용과 새 탭 생성, AI 상태 보존을 확인했다. 헤더와 이미지 지연 중 placeholder를 유지하고 해제 후 미리보기를 자동 생성하는 동작, 로컬 CEF 22개도 통과했다. 다만 검색 중 현재 탭을 닫으면 입력 포커스를 잃는 결함이 있었으며 v3는 닫히는 CEF 뷰 내부의 responder만 해제하도록 수정했다. v2의 미리보기, CEF 결과를 v3 완료 증거로 합산하지 않는다. 근거는 `artifacts/search-preview-v2-native.json`, `artifacts/search-preview-v2-delays.json`, `artifacts/search-preview-v2-suite.json`이다.

이전 북마크 v1(`bd7baf100fd434e0898fa98c9453988fb5b531ed205d5eea86f4e27f6c828dbd`)은 Rust 124개와 로컬 CEF 22개를 통과했다. `artifacts/bookmarks-v1-native.json`은 실제 저장·검색·고정 URL·탭 재사용과 정상 종료 후 재실행 보존, 마지막 항목 삭제를 확인했다. `artifacts/bookmarks-v1-recovery.json`은 손상 프로필의 읽기 전용 UI와 정상 백업 열기, 본문·백업 해시 보존, 정상 종료 및 임시 프로필 삭제를 확인했다. 이 결과는 v2에 합산하지 않으며 [북마크 설계](bookmarks-design.md)에 실행 범위를 기록한다.

v2 미리보기는 observer 등록과 완성된 현재 문서를 확인하고 CEF 로딩 조회 뒤 상태를 재검사한 후 캡처 자리를 예약한다. v2에서 지연 문서의 실제 미리보기 생성 시점을 확인했다. 이 예방 수정으로 과거 승인 대기나 캡처 정체의 원인이 확정됐다고 설명하지 않는다.

본문 입력 인계와 주소 탐색의 이전 증거는 `artifacts/daily-browser-v6-rust-tests.log`의 Rust 117개, `artifacts/daily-browser-v6-suite.json`의 로컬 CEF 22개, `artifacts/daily-browser-v6-native.json`이다. 이 v6 바이너리에는 북마크 UI·런타임이 없으며 이후 버전의 결과와 합산하지 않는다.

내장 대화·모델 연결, 작업 기록·메모리·반복 작업은 이번 사용자 선택에 따라 일상 사용성 뒤에서 검토한다. 확인하지 않은 Aside 기능 전체를 현재 Naru 요구사항이나 구현 기능으로 표시하지 않는다. 북마크는 승인된 JSON 파일·정상 백업 한 개·모든 공간 공유·최대 1,000개와 2MiB를 적용한다. 탭 복원 등 다른 영속 저장 방식과 데이터 이전은 구현 전에 별도로 구체화한다.

## 페이지 내 찾기 진행

[페이지 찾기 설계](page-find-design.md)와 `artifacts/find-page-v1-native.json`에 로컬 검색·이동·순환·본문 입력·화면 전환과 AI 제어권 검증을 기록했다. 실제 검사에서 발견한 task resume의 찾기 만료 누락은 해당 작업의 탭만 기존 취소 경로로 전달하도록 수정했다. 새 회귀를 포함해 Rust 137개, format과 release 빌드가 통과했다.

페이지 찾기 v2 검증 번들은 SHA-256 `458ee5ad7a075d2a0b3c35b1d75f037847976e7711720b7319529eea1e0ea427`다. 첫 로컬 load 대기는 키체인 승인 전 `WAIT_TIMEOUT`이었지만 사용자가 항상 허용한 뒤 같은 바이너리와 탭의 HTTP 완료를 확인했다. `artifacts/find-page-v2-native.json`에서 기본 `needle 1/8→2/8→1/8`, A의 잘못된 revision 재개 거절 후 검색·포커스 보존, B의 handoff·재개 후 A의 찾기 보존을 확인했다. A의 정상 재개는 찾기 막대와 실제 주황·노랑 강조를 제거했고 `⌘G`가 이전 검색어를 복구하거나 A/B의 active·revision 3을 바꾸지 않았다. 새 `⌘F`는 빈 입력과 A의 새 handoff로 시작했고 한국어 붙여넣기는 `1/5`였다. 검증 A/B는 각각 finished·revision 5/4와 빈 탭 목록으로 정리했으며 기존 사용자 빈 탭 1을 보존했다.

같은 v2의 작업 6개·공간 10개·단일 창 6개, 총 22개 CEF 회귀가 모두 exit 0·빈 stderr로 통과했다. 생성한 작업 7개를 모두 finished·빈 탭 목록으로 정리했고 기존 빈 탭 1과 대기·캡처·생성 예약 0을 확인했다. 근거는 `artifacts/find-page-v2-suite.json`, `artifacts/find-page-v2-suite-state.json`이다. 최초 샌드박스 읽기의 `SOCKET_IO_ERROR`·`outcomeUnknown:false`는 `*-sandbox.json` 두 파일에 보존했고 실행 권한을 받은 재시도 결과와 구분했다.

v2의 네이티브 종료 메뉴를 실행한 뒤 앱 세션 exit 0을 확인했고, 같은 프로필·바이너리로 재시작한 뒤 추가 승인 없이 로컬 HTTP 로딩과 화면 표시를 확인했다. 검증 탭을 닫고 기존 빈 탭 1·대기·캡처·생성 예약 0으로 돌아왔으며 빈 북마크 목록도 확인했다. 이전 앱 프로세스는 없고 검증용 HTTP 서버는 종료했다. 검사 후와 재시작 후 각 6개 프로세스의 RSS 세 표본도 기록했다. 공유 메모리 중복과 실행 조건 차이가 있어 두 시점이나 이전 v3와의 차이를 메모리 절감 효과로 판단하지 않는다. 수치와 조건은 [메모리 문서](memory.md)에 있다.

IME 조합·좁은 창·외부 사이트·장시간 사용은 남아 있다. v1은 정상 종료 exit 0으로 교체했고 빌드 중간 파일 3,537개·1.9GiB를 정리했다. 빌드·대기·재시작과 정리 기록은 `artifacts/find-page-v2-validation.json`에 있다. 키체인 대기는 해소됐고 2026-10-11 후속 조회에서 목표 도구는 `active`를 반환했다. 전체 독립 브라우저 목표는 남은 기능과 검증 때문에 미완료다. 같은 바이너리의 재실행은 확인했으며 재서명 후 무승인 실행까지 해결한 것은 아니다.

후속 입력 검사에는 저장·전송 없이 최근 이벤트 20개만 유지하는 `/ime-input.html` fixture를 추가했다. 같은 v2에서 HTTP 완료, 한글 문구 찾기 `1/1`, 205자 붙여넣기의 200자 제한, 사이드바 접기 후 찾기 값과 포커스 유지, Esc 닫기를 확인했다. CUA의 `r`·`k`는 trusted `insertText`로 각각 들어왔지만 composition 이벤트는 모두 0이었다. 실제 IME 성공이나 제품 결함으로 판정하지 않는다. 창 테두리 드래그도 크기를 바꾸지 못해 최소 크기 화면 검증은 남았다. 근거는 `artifacts/input-layout-v1-native.json`, 재현과 판정 기준은 [입력 검증 절차](input-validation.md)에 있다. 제품 코드와 승인된 바이너리는 바꾸지 않았다.

## 유지할 원칙

[최근 닫은 탭 다시 열기](reopen-closed-tabs.md)는 URL만 기억하는 실행 중 편의 기능이다. 프로필에 저장하는 세션 복구, 방문 기록 검색이나 폼·뒤로가기 복원 완료로 확대하지 않는다.

재열기 v1에서는 역순 복구·beforeunload 취소·AI 탭 제외·overlay 보호를 확인했지만 AI 본문의 ⌘⇧T가 작업을 중지하는 결함을 발견했다. v2 SHA-256 `84bfaf36d80d6b6048461b07fcbef5c5bca2862c3408aa7d2e772e1fa5204100`는 macOS 수정키를 적용해 문자를 재번역하고 단축키를 먼저 소비한다. Rust 144개·전체 타깃과 로컬 CEF 22개가 통과했다. 실제 네이티브 입력에서 사용자 탭 역순 복원, AI active·revision 보존과 본문 키 차단, 재개 후 동일 보호를 확인했다. 정상 종료·동일 바이너리 재시작 뒤 복원 목록 초기화와 HTTP 로딩도 확인했다. 원래 빈 사용자 탭을 보존하고 테스트 작업·탭·서버와 이전 앱을 정리했다. v1과 v2의 검증 범위·한계는 `docs/reopen-closed-tabs.md`, 종합 근거는 `artifacts/reopen-v2-validation.json`에 있다.

- Rust·CEF·Chromium과 네이티브 AppKit UI, 하나의 브라우저 창, 외부 CLI를 유지한다.
- 화면 구성은 Naru에 맞게 만들고 참고 제품의 로고·브랜드나 자산을 복제하지 않는다.
- 표시 공간은 로그인 격리가 아니다. 계정별 프로필 설계와 분리해서 설명한다.
- 사용자 개입은 현재 상태로 제어권을 확인하고 기존 중지 경로를 사용한다. 페이지 JavaScript가 보내는 합성 이벤트로 사용자 개입을 판정하지 않는다.
- 이미 전달된 변경 작업을 되돌렸다고 표시하지 않으며 결과 확인이 필요하면 그 상태를 반환한다.
- 브라우저 전체의 메모리를 측정한다. Rust 사용과 단일 창이 낮은 메모리 사용을 자동 보장하지 않는다.
- 앱 교체 후 이전 프로세스와 빌드 중간 파일을 정리하고 사용자 탭·프로필을 보존한다.
- 매 작업의 변경·검증·한계·정리는 [작업 기록](work-log.md)에 남긴다.

## 페이지 확대 API 검토 — 구현 보류

페이지 확대 기능은 구현하지 않았으며 UI 초안은 되돌렸다. 설치된 CEF 156 공개 헤더의 `Zoom`·`CanZoom`·`SetZoomLevel` 계약과 현재 공식 CEF·Chromium 소스를 읽기 전용으로 검토했다. 설치 바이너리에 고정된 CEF 커밋의 구현 원문과 실제 확대 동작은 검증하지 않았으므로, 아래는 API·설계 근거이며 실행 결과가 아니다.

Naru는 탭마다 global request context를 사용한다. 공식 구현의 기본 확대는 공유 host 값에 기록되며, HTTP(S)의 키는 끝 점을 제거한 host로 scheme·port를 포함하지 않는다. 현재 열린 탭이나 요청 URL의 충돌만 막아도 이후 같은 host로 이동하는 AI 탭에 영향을 줄 수 있어, 현재 탭 목록만 검사하는 방어로는 작업 격리를 보장할 수 없다. [CEF 확대 호출 경로](https://github.com/chromiumembedded/cef/blob/master/libcef/browser/browser_host_base.cc), [Chromium 확대 처리](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/components/zoom/zoom_controller.cc), [host 키 생성](https://chromium.googlesource.com/chromium/src/+/main/net/base/url_util.cc).

Chromium 내부에는 탭별 temporary/isolated 확대가 있지만 설치된 CEF 공개 API에는 모드 설정이 없고, 내부 격리 모드도 문서 탐색 시 초기화된다. Chromium은 host 확대값의 프로필 저장·복원 경로도 갖지만 Naru의 재시작 보존은 미검증이다. 후속 구현은 엔진과 호스트의 경계에서 탭별 확대·탐색·기본값 복원·저장 정책을 설계하고, 다른 AI 탭에 영향이 없음을 검증한 뒤 진행한다. [격리 모드와 탐색 처리](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/components/zoom/zoom_controller.cc), [확대값 저장·복원](https://chromium.googlesource.com/chromium/src/+/lkgr/chrome/browser/ui/zoom/chrome_zoom_level_prefs.cc).
