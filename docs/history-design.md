# 방문 기록과 통합 검색

기준일: 2026-10-15. 사용자가 승인한 **내 공간만 기록** 정책을 소스로 구현했다. 실제 앱은 실행하지 않았고 사용자 프로필의 기록 수집도 시작하지 않았다. 단위 검사와 최종 앱 검증은 아래와 작업 기록에서 구분한다.

## 승인한 저장 정책

| 항목 | 구현 정책 |
| --- | --- |
| 위치 | 기존 config::data_dir 아래 history-v1.json |
| 저장 | JSON 한 개의 원자적 교체. 별도 DB나 상주 프로세스 없음 |
| 백업 | 과거 방문 목록의 백업을 만들지 않음. 북마크 백업은 유지 |
| 범위 | 내 공간에 있고 AI 작업 소유가 없는 탭의 확인된 HTTP(S) 문서 |
| 보존 | 최근 30일, 최대 1,000개 URL, 직렬화 파일 최대 2MiB |
| 중복 | 정규화 URL이 같으면 안정적인 ID를 유지하며 최근 방문 시각과 제목 갱신 |
| 정보 | ID, 전체 URL, 표시 제목, 마지막 방문 시각 |
| 제외 | 본문, 폼 값, 비밀번호, 스크린샷, 쿠키 복사본 |
| 검색 | 모든 공간에서 통합 검색과 방문 기록 전용 보기 제공 |
| 삭제 | 검색어와 관계없이 방문 기록 전체 삭제. 쿠키, 로그인, 북마크, 열린 탭 보존 |

URL에는 query와 fragment를 포함한다. 기존 `address::normalize_url`의 HTTP(S), credentials 거절과 길이 제한을 적용하며 검색어 해석 함수 `resolve`는 쓰지 않는다. 제목은 제어 문자를 제거하고 최대 256자로 제한한다. 제목이 없으면 제한된 URL을 표시한다. 원문 URL을 진단 로그에 추가하지 않는다.

상한을 넘으면 오래된 기록부터 제거한다. 기간은 시스템 시각 기준이며 시계를 과거로 돌리면 미래 시각의 기록은 나이를 0으로 계산해 실제 보존 기간이 길어질 수 있다. 개수와 파일 크기 제한은 계속 적용한다. 공간은 프로필을 공유하며 이 기능도 로그인 격리를 만들지 않는다.

## 문서 확인과 AI 작업 제외

`browser.rs`의 CEF 콜백은 탭별 `HistoryObservation`에 후보만 갱신한다. 요청 URL이나 `on_address_change` 하나를 방문 완료로 판정하지 않는다. main frame의 commit과 HTTP 상태 200 이상 599 이하인 로드 완료를 받은 뒤, 지연 UI 작업에서 로딩 종료, 문서 준비, 오류 없음과 실제 main frame URL을 확인한다. CEF 조회 전후 탭 ID, 탐색 세대, 문서 세대, 공간, 소유권과 요청 주소의 일치 여부를 재검사한다. 4xx와 5xx 웹 문서도 기록 대상이지만 네트워크 오류 화면은 제외한다. 다운로드, 204 등 실제 문서 commit이 없는 요청도 제외 대상이며 실제 CEF 콜백 순서 검증은 남는다.

탭당 지연 관찰 작업은 하나로 합친다. 성공 문서의 같은 문서 fragment와 history API 이동은 확인된 새 주소의 방문으로 처리한다. 제목이 늦게 오면 기존 항목의 제목만 갱신하며 방문 시각을 바꾸거나 없는 항목을 만들지 않는다. 탭 종료, 탐색 오류, 중지, 렌더러 종료와 소유권 이전은 이전 후보의 자격을 무효화한다.

내 공간의 unowned 탭만 기록한다. 사용자가 AI 작업을 중지했어도 AI 공간에 남은 탭은 대상이 아니다. AI가 시작한 탐색을 release한 뒤 완료하거나 기존 AI 문서를 내 공간으로 옮겨도 기록 대상으로 승격하지 않는다. 새 사용자 탐색에서 자격을 다시 잡는다. 이는 실제 입력 장치의 증명이 아니며 내 공간의 소유되지 않은 탭을 CLI로 탐색하면 기록할 수 있다.

북마크, 방문 기록과 현재 주소 복사를 위한 숨은 새 탭은 생성 시 기록 세대를 고정한다. 최종 검증과 사용자 선택에 성공할 때까지 수집을 보류한다. 생성 중 CEF 콜백이 먼저 완료돼도 실패한 임시 탭은 기록하지 않는다.

## 검색과 열기

`tab_search.rs`는 Tab, Bookmark, History 종류와 ID를 함께 유지한다. 탭, 북마크, 최신 방문 기록 순서로 전체 40개까지 표시한다. 앞선 결과에 같은 정규화 URL이 있으면 방문 기록만 중복 제외한다. 방문 기록 전용 보기에서는 열린 탭 수와 관계없이 최신 기록을 최대 40개까지 검색한다. 검색어는 최대 200자다. 전체 목록의 소문자 캐시나 썸네일을 만들지 않는다.

`control_panel.rs`는 기존 네이티브 검색 화면과 행을 재사용한다. 보기 메뉴의 방문 기록과 검색 화면의 모드 전환 버튼으로 진입하고, 모드 전환과 삭제 후에도 검색어를 유지한다. 전체 삭제는 같은 화면의 확인, 취소 버튼으로 실행하며 Esc는 먼저 삭제 확인을 취소한다. 별도 창이나 UI용 웹 renderer는 추가하지 않았다. 숨기거나 제거한 버튼이 포커스를 가졌다면 검색 입력으로 복구하고 유효한 편집기와 컨트롤은 유지한다. 실제 AppKit 포커스와 IME, 최소 창 배치는 미검증이다.

기록을 열기 직전에 런타임의 현재 ID, 삭제 세대와 만료를 확인한다. `history_runtime::open → browser::open_history_url → open_saved_user_url`은 사용자 공간의 안전한 같은 주소 탭을 재사용하거나 숨은 새 사용자 탭을 만든다. 생성 전후 기록과 현재 선택이 바뀌었으면 기존 선택을 유지하고 실패한 생성물을 정리한다. AI 소유 탭은 재사용하지 않는다. 열기 오류는 검색 화면에 표시한다. 이 기능은 폼, 뒤로가기 목록이나 세션 복원을 구현하지 않는다.

## 파일 처리와 삭제 순서

`history.rs::Store`는 제한된 읽기와 역직렬화, 파일 소유권과 권한, symlink와 hardlink, 디렉터리 교체와 외부 파일 변경을 검사한다. 손상 또는 외부 변경을 감지하면 기존 파일을 자동 초기화하지 않고 쓰기를 중단한다. 임시 `.history-v1.json.pending`에 쓰고 파일 동기화, rename, 폴더 동기화 순서로 반영한다. 과거 목록 백업이나 남은 pending 파일의 자동 승격은 없다. rename 후 폴더 동기화 실패는 반영 취소로 가장하지 않고 내구성 경고로 구분한다.

`history_runtime.rs`는 한 번에 파일 worker 하나를 실행한다. 그동안 온 후보는 최대 64개, URL과 제목의 UTF-8 합계 256KiB 대기 목록에서 같은 URL끼리 합친다. 가득 찼을 때 새 방문은 오래된 대기를 제외하며 안내를 남기고, 새 제목 갱신만으로 대기를 늘리지 않는다. Store와 게시용 메타데이터 캐시, 작업 중인 목록은 각각 제한되지만 이 수치는 전체 프로세스 RAM 상한이 아니다. 파일 I/O는 UI 스레드 밖에서 처리하며 타이머나 상주 worker는 없다.

전체 삭제 요청은 즉시 세대를 증가시키고 이전 대기를 버린다. 진행 중 쓰기, 전체 삭제, 새 세대 쓰기 순서로 처리하며 삭제 중에는 과거 결과를 숨긴다. 완료된 파일 교체를 받은 뒤에만 삭제 중 표시를 해제한다. 실패하면 오류와 읽기 전용 상태를 표시하며 성공으로 처리하지 않는다. 삭제 이전 ID와 늦은 방문, 제목 콜백은 거절한다. **삭제 당시 열린 문서는 이후 SPA 또는 fragment 이동도 다음 전체 탐색 전까지 기록하지 않는다.** 삭제 이후 새 전체 탐색은 새 세대의 기록이 될 수 있다.

시작할 때 만료된 항목은 메모리에서 제외하고 유효한 파일이면 별도 worker에서 디스크도 정리한다. 이후 검색과 열기는 현재 시각으로 만료를 제외한다. 정상 종료는 생산을 닫고 진행 중 작업, 삭제와 제한된 후속 쓰기를 마무리한다. 완료 알림 전달이 빠져도 다음 접근이나 종료에서 결과를 회수한다. 실제 강제 종료 뒤 복구는 후속 앱 검사 대상이다.

## 검증 상태와 남은 범위

Rust 단위 231개, 기본 기능과 CLI 구성 전체 타깃 Cargo 검사, format과 diff 검사가 통과했다. 저장소 15개, 런타임 5개, 수집과 열기 3개, 검색 2개가 새 검사다. 소스 검사 결과와 생성물 정리는 `docs/work-log.md`와 `artifacts/history-v1-validation.json`에 기록했다. 임시 디렉터리의 파일 검사, 비활성 CEF 핸들을 쓰는 상태 검사, 순수 검색 모델 검사는 실제 CEF 엔진과 네이티브 화면 검증을 대신하지 않는다.

다음 최종 앱 검증은 아직 실행하지 않았다.

1. 로컬 HTTP의 redirect, 실패, 204, 다운로드와 실제 4xx 문서, 늦은 제목, 같은 문서 이동 수집.
2. AI 배경 탐색, adopt와 release, 삭제와 생성이 겹칠 때 선택과 기록 보존.
3. 검색 모드, 키보드 선택, 전체 삭제 확인과 취소, 한글 IME와 최소 창 배치.
4. 정상 재실행과 강제 종료, 장시간 방문 부하와 프로세스 메모리.
5. 외부 사이트 호환성과 Preseller 내장.

앱 실행과 키체인 반복 요청은 중단한 상태다. 기존 앱 바이너리에 이번 기능을 반영했다고 주장하지 않는다. 전체 독립 브라우저와 Preseller 내장 목표는 계속 미완료다.
