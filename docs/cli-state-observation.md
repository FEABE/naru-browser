# CLI의 탭 상태 관측

기준일: 2026-10-16. CLI 탭 목록, 로딩 대기와 탐색 진단에서 CEF 조회와 내부 상태 접근을 분리하는 계약이다. 실제 Naru 실행 검증과 소스 검사 결과는 [작업 기록](work-log.md)에서 구분한다.

## 관측과 응답

탭의 원래 Browser, 탐색과 문서 세대, 로딩 관측 세대를 잡은 뒤 STATE borrow 밖에서 CEF 값을 읽는다. 각 조회 경계에서 요청의 활성 여부와 필요한 작업 권한을 확인한다. `tab_info`는 유효한 관측 값과 현재 내부 상태로 JSON을 만드는 순수 함수다. 응답을 조립할 때 CEF를 다시 호출하지 않는다.

CLI의 `url`은 실제 main-frame URL이다. 아직 commit되지 않은 요청의 `navigation.requestedUrl`이나 네이티브 주소 표시로 대체하지 않는다. 프레임이 없는 경우의 빈 문자열 의미도 유지한다. 정상 응답의 로딩, 히스토리 이동 가능 여부, renderer와 navigation 필드는 기존 의미를 따른다.

작업 범위의 `tabs`는 해당 작업의 현재 revision과 소유 탭을 다시 확인한다. 범위 없는 `tabs`는 기존처럼 모든 작업의 탭 메타데이터를 볼 수 있다. 전체 조회 중 대상이나 페이지가 바뀌면 일부 탭만 성공 목록으로 내보내지 않는다. 이 경우 읽기 오류를 반환하며 자동으로 명령을 반복하지 않는다. 사용자 공간 선택과 AI 제어권은 조회로 변경하지 않는다.

`open`에서 탭 생성은 끝났지만 상태 관측이 실패한 경우에는 오류의 세부 정보에 `tabCreated:true`, `tab`, `stateUnavailable:true`, `outcomeUnknown:false`를 포함한다. 생성 사실과 상태 조회 실패를 구분하며, 이 응답만 보고 open을 반복하지 않는다. 생성된 탭이 지금도 살아 있거나 요청한 문서의 로딩이 끝났다는 뜻은 아니다.

## 로딩 대기

대기 항목은 상태 관측을 시작하기 전에 삭제하지 않는다. 원래 요청의 활성 표시와 작업 권한, 대기 항목의 identity, 절대 마감 시간을 관측 뒤에도 확인한다. 늦은 DOM 결과가 취소나 제어권 인계로 끝난 요청을 되살리면 안 된다.

로딩 관측이 불안정하면 기존 50ms tick에서 다시 확인하되 시작 시간과 제한 시간을 초기화하지 않는다. DOM 준비 상태의 CDP 요청은 대기당 최대 하나를 유지한다. 성공 응답은 준비 상태와 같은 문서의 유효한 탭 관측을 확보한 뒤에만 대기 항목을 제거한다.

준비 상태 확인의 각 CDP 단계는 host와 파라미터를 준비한 뒤 원래 Browser, 문서, 작업 소유권, 대기 시작 시간과 활성 요청을 다시 검사한다. 같은 숫자 token만으로 이전 callback이나 예약 tick을 새 대기에 연결하지 않는다. 최종 DOM 응답도 callback의 원래 Browser와 현재 관측이 일치해야 채택한다. 이 처리는 일반 페이지 변경 명령의 자동 재시도를 추가하지 않는다.

renderer 종료, 명시적 중지, 미완료 탐색과 탐색 실패의 기존 판정을 유지한다. 제한 시간 안에 일관된 상태를 읽지 못해도 대기를 무기한 늘리지 않는다. `WAIT_TIMEOUT`의 `tab`, `until`, `timeoutMs`, `elapsedMs`, `navigationContinues:true`는 유지한다. 이때 native 상태를 확정하지 못한 경우는 `state:null`, `stateUnavailable:true`로 명시하며 이전 페이지 상태를 성공 근거로 반환하지 않는다. 대기 시간 초과는 탐색이나 탭을 자동 중지하지 않는다.

대기 중 renderer 종료나 탐색 실패를 먼저 확인한 경우에도 관측에 실패했다면 같은 `state:null`, `stateUnavailable:true`를 사용할 수 있다. 이 필드는 원래 실패 종류를 바꾸는 것이 아니라 부가 상태를 읽지 못했음을 나타낸다.

외부 소켓 요청의 45초 마감은 `wait`의 1~30,000ms 제한과 별개다. 최종 응답은 기존 Reply의 활성 플래그로 한 번만 보낸다.

## 탐색 요청

탐색의 히스토리 이동 가능 여부와 현재 로딩 상태도 borrow 밖에서 읽는다. 진행 중인 탐색의 `NAVIGATION_BUSY`, 히스토리가 없는 `NO_HISTORY`, 직접 URL 이동에 필요한 `FRAME_UNAVAILABLE`의 의미는 유지한다. renderer 복구를 위한 뒤로가기, 앞으로가기와 새로고침에는 사용 가능한 main frame을 요구하지 않는다.

다운로드 권한 대기와 찾기 정리는 새 탐색 의도를 기록하기 전에 실행한다. 정리 중 문서, 제어권이나 원래 Browser가 바뀌면 새 탐색을 보내지 않는다. 마지막 검증 뒤 탐색 의도를 기록하고 바로 CEF에 전달한다. 성공의 `navigationRequested:true`는 요청 수락이며 문서 로딩 완료가 아니다.

사람이 조작하는 네이티브 탐색과 CLI 권한은 구분한다. CLI는 기존 작업 revision과 소유권을 검사하고 배경 탭을 대상으로 할 수 있다. 네이티브 경로에서는 중지한 AI 탭을 사람이 직접 사용할 수 있어야 하며, 조회나 정리 중 현재 선택과 공간이 바뀌면 이전 탭에 명령을 보내지 않는다.

## 범위와 자원

관측 동안 현재 대상의 Browser 참조와 값만 보관한다. 새 영속 저장, worker, renderer나 반복 타이머는 추가하지 않는다. 목록 관측은 현재 대상 탭 수에 비례하고 단일 탭과 대기는 해당 탭 하나를 확인한다. 실제 RAM 절감량이나 응답 속도 개선을 측정한 결과는 아니다.

실제 Naru에서 리디렉션과 느린 HTTP 응답, 중지와 닫힘, AI 인계와 재개, DOM 응답 지연을 함께 실행하는 검증은 남아 있다. 네이티브 경계를 주입한 단위 검사를 실제 CEF의 실행 증거로 대신하지 않는다.
