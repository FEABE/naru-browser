# 브라우저 화면의 상태 읽기

기준일: 2026-10-16. 단일 AppKit 창의 탭 목록과 탐색 막대를 갱신할 때 사용하는 상태 읽기 경계다. 실제 앱에서 재진입 오류가 재현됐다는 기록과 소스에서 확인한 borrow 충돌 가능성을 구분한다.

## 조회와 반영

`shell_snapshot`은 현재 탭의 Browser 참조와 탐색, 문서, 로딩 관측 세대를 짧게 캡처한다. 내부 상태의 borrow를 해제한 뒤 Chromium의 로딩, 뒤로가기, 앞으로가기 가능 여부를 읽는다. 각 네이티브 조회 전후에 원래 탭이 같은 Browser와 세대를 유지하는지 검사한다.

모든 탭을 읽은 뒤 전체 관측을 다시 검사한다. 뒤쪽 탭을 조회하는 동안 앞쪽 탭이 바뀐 경우도 이전 결과를 사용하지 않는다. 이 최종 상태에서 제목, 공간별 탭 순서, 선택과 AI 소유권을 함께 조립한다. 조회가 끝나기 전에 새 탭이 생겨 관측이 없으면 그 탭을 목록에서 빼는 대신 전체 갱신을 보류한다.

로딩 시작과 완료는 탐색 세대가 바뀌지 않고 발생할 수 있다. `OnLoadingStateChange`를 받을 때 별도 관측 세대를 올려 이전 표본을 무효화한다. 로딩 콜백만으로 뒤로가기 상태를 대체하지 않고 실제 CEF getter 조회를 유지한다.

## 갱신 보류

조회 중 대상이 바뀌거나 스냅샷 조회가 중첩되면 `None`을 반환한다. 빈 탭 목록을 화면에 전달하지 않는다. 기존 화면을 유지하고 기존 100ms 갱신 예약으로 다음 조회를 합친다. 다운로드 파일 위치 표시처럼 현재 선택을 검증하는 호출도 상태 확인에 실패하면 실행을 중단한다.

스냅샷의 유효성은 반환 시점까지의 보장이다. 반환 이후 AppKit 배치나 다른 CEF 호출이 일으키는 재진입까지 원자적으로 막는 기능은 아니다. 명령 실행 직전 대상 검증은 각 동작의 기존 책임으로 유지한다.

로딩 중지나 인계 후 실패의 주소 초안은 화면 갱신 성공 여부에만 의존하지 않는다. 명령 결과가 보존을 허용한 경우 갱신 전에 원래 Browser, 문서와 소유권을 잡고, 갱신 후 네이티브 호출 없이 다시 확인한다. 로딩 관측만 바뀌거나 다른 탭 때문에 스냅샷을 보류한 경우도 같은 문서의 초안을 유지한다. 실제 문서나 제어권이 바뀌면 그 근거를 폐기한다. 주소 문자열을 다시 쓰거나 보존 상태를 다음 작업까지 연장하지 않는다.

## 자원과 남은 범위

한 번의 조회 동안 현재 탭 수에 비례한 Browser 참조와 작은 관측 값을 보관한다. 탭별 로딩 세대와 조회 중첩 표시 외에 장기 캐시, 새 worker, 반복 타이머, renderer나 저장 파일은 추가하지 않는다. 실제 RAM 감소량을 측정한 결과는 아니다.

CLI의 `tab_info`와 탐색 시작은 후속 [CLI 관측 계약](cli-state-observation.md)으로 별도 보완한다. CLI의 실제 main-frame URL과 네이티브 화면의 requested URL은 의미가 달라 통합하지 않는다. 전체 AppKit 렌더 과정의 재진입 경계는 여전히 별도 점검 대상이다. 실제 Naru의 빠른 탭 닫기, 공간 전환, 탐색 완료와 주소 편집, AI 배경 작업의 동시 실행도 검증이 남아 있다. 실행한 단위 검사와 컴파일, 미실행 앱 검증은 [작업 기록](work-log.md)에 구분한다.
