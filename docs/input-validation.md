# 한글 입력과 좁은 창 수동 검증

기준일: 2026-10-11. 페이지 찾기 v2와 로컬 [입력 fixture](../tests/fixtures/ime-input.html)를 확인하는 절차다. 아래 실행할 절차는 완료한 검사 결과가 아니다.

## 현재 근거

[fixture 검사 기록](../artifacts/ime-input-fixture.json)에는 HTML 정적 검사와 Python 구문 검사, 격리 HTTP 응답 및 서버 종료 확인 7개가 있다. 실제 입력기 조합이나 창 배치를 검증한 결과는 아니다.

같은 v2 앱에서 CUA로 `r` 다음 `k`를 입력했을 때 본문 값은 `ㄱㅏ`였다. 신뢰된 `beforeinput`과 `input`이 각각 두 번 발생했고 `inputType`은 `insertText`, `isComposing`은 false였다. `compositionstart`, `compositionupdate`, `compositionend`는 모두 0이었다. [실제 이벤트 기록](../artifacts/input-layout-v1-native.json)에 근거하며, 이 시도로 IME 성공이나 제품 결함을 판정할 수 없다. `isTrusted:true`만으로 실제 조합을 입증하지 않는다.

fixture는 최근 이벤트 20개와 종류별 누적 횟수, 조합 상태 및 UTF-16 길이를 표시한다. 문자 원문은 입력칸에만 남고 이벤트 기록에 복제하지 않는다. 페이지는 입력을 저장하거나 전송하지 않으며 초기화 버튼으로 입력과 기록을 지울 수 있다. 검사자가 별도로 보관하는 화면과 CLI 기록은 이 페이지의 저장 동작과 구분한다.

## 직접 키보드로 확인할 절차

1. 프로젝트 디렉터리의 터미널에서 아래 명령으로 로컬 서버를 시작한다. 시작 JSON의 `urls`에서 `/ime-input.html`에 해당하는 실제 URL을 복사해 별도 검증 탭으로 연다. 포트와 탭 ID를 추정하거나 이전 실행 값을 재사용하지 않는다.

   ```sh
   python3 tests/preview_fixture.py --port 0
   ```

2. macOS 입력 메뉴에서 사용하는 한글 입력기를 확인하고 이름을 기록한다. fixture의 초기화 버튼을 누른 뒤 본문 입력칸을 클릭한다. 붙여넣기나 자동화 입력 대신 물리 키보드로 한글을 입력한다. 두벌식이면 `r`, `k`를 차례로 누르며 실제 조합 표시와 `가`로 합쳐지는지 확인한다. 조합 중과 Enter로 확정한 뒤의 이벤트를 각각 기록한다.
3. 초기화 후 같은 입력을 반복하고 조합 중 Esc를 누른다. 조합 취소 또는 확정, 포커스와 실제 입력값을 관찰한다. 이벤트의 정확한 순서를 미리 단정하지 말고 입력기 이름과 함께 남긴다. 한글 붙여넣기도 별도 실행해 직접 조합과 구별한다.
4. 찾기 막대를 열고 본문을 다시 클릭해 조합한다. 조합 중 `⌘F`, `⌘G`, Esc를 각각 별도 시도로 확인한다. 주소창, 통합 검색, 북마크 편집 입력, 페이지 찾기 입력에서도 직접 조합과 Enter 및 Esc를 각각 확인한다. 본문 DOM 이벤트 기록은 이 네이티브 입력칸의 동작을 증명하지 않으므로 실제 조합 표시, 포커스, 입력값과 실행된 동작을 따로 기록한다.
5. 창을 줄여 콘텐츠 영역의 최소 크기인 800×520pt에서 반복한다. 이 값은 소스의 `setContentMinSize` 기준이며 창 외곽이나 스크린샷 픽셀 크기와 다르다. 실제 콘텐츠 크기를 확인할 수 없다면 최소 크기 검증으로 기록하지 않는다. 세로 탭을 펼친 경우와 접은 경우에 주소창, 찾기 막대, 통합 검색 및 북마크 편집 화면을 각각 확인한다.
6. 검증 탭만 닫고 원래 공간과 탭을 선택한다. 이번에 시작한 서버는 해당 터미널에서 Ctrl+C로 종료한다. 다른 앱 프로세스나 사용자 프로필은 정리 대상에 포함하지 않는다.

## 확인해야 할 결과

- 본문에서 직접 조합이 실제 발생했는지 화면의 조합 표시와 조합 이벤트로 확인한다. 조합 이벤트가 계속 0이면 입력 경로를 확인해야 하며 성공이나 제품 결함으로 결론내리지 않는다.
- 조합 중 Enter가 다음 찾기, 검색 실행이나 북마크 저장을 성급하게 수행하지 않는다. 찾기 단축키가 조합 중 포커스를 가져가거나 막대를 닫지 않는지 확인한다. 조합을 확정한 뒤에는 해당 명령이 정상 작동해야 한다.
- 네이티브 입력칸은 조합 문자와 초안, 커서 위치를 유지한다. 막대에서 본문으로 클릭한 뒤에는 본문 입력이 가능해야 한다. 입력칸별 결과를 따로 기록한다.
- 최소 콘텐츠 크기에서 필수 입력과 닫기, 이전 및 다음 버튼이 겹치거나 잘리지 않고 실제 클릭과 키 입력이 가능하다. 결과 목록과 긴 제목도 가로 넘침을 일으키지 않는지 확인한다. 다른 크기에서의 성공으로 이 조건을 대신하지 않는다.

실제 화면 확인, 본문 이벤트 관찰, 소스와 HTTP 검사를 구분해 [작업 기록](work-log.md)에 남긴다. 이 절차는 외부 사이트, 모든 입력기 또는 장시간 사용을 검증하지 않는다.
