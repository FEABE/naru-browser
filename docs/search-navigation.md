# 통합 검색에서 새 탐색 열기

통합 검색은 열린 탭, 북마크와 방문 기록을 먼저 보여준다. 2026-10-16 후속 소스는 그 아래에 입력한 주소를 열거나 Google에서 검색하는 명시적 행을 추가한다. 결과가 없는 검색어도 같은 화면에서 탐색으로 이어진다. 방문 기록만 보는 모드에는 이 행을 추가하지 않는다.

## 입력과 실행

- 기존 주소창의 `address::resolve_with_kind`로 주소와 검색어를 구분한다. `resolve`도 같은 해석을 사용한다. 직접 입력한 Google 검색 URL은 주소로 표시하며 URL의 모양만으로 검색어였다고 추정하지 않는다.
- 입력 중에는 외부 추천 요청, 페이지 미리 열기와 원격 검색을 하지 않는다. 사용자가 해당 행을 클릭하거나 선택한 상태에서 Enter를 눌러야 탐색한다. 일치하는 내부 결과가 있으면 기존과 같이 그것을 먼저 선택한다.
- 빈 입력, 잘못된 주소, 지원하지 않는 스킴과 자격정보가 포함된 주소에는 새 탐색 행을 제공하지 않는다. 입력 오류를 검색 서비스로 보내는 대체 경로는 없다.
- 입력은 기존 200자 상한을 유지한다. 너무 긴 입력을 붙여넣어 표시 문자열이 잘렸으면 새 탐색을 막고 수정 안내를 표시한다. 프로그램이 잘린 문자열을 다시 통지해도 제한 표시를 지우지 않는다. 사용자가 입력을 다른 값으로 바꾸면 다시 판단한다.
- 전체 결과는 최대 40개다. 새 탐색 행을 제공할 때 그 한 자리를 포함하며 탭, 북마크와 기록의 상대 순서는 유지한다.

검색어와 모드, 열기와 닫기의 세대로 실행 대상을 구분한다. 오래된 행을 눌렀거나 실행 전에 검색어가 바뀌면 그 행의 주소를 열지 않는다. IME 조합 중 새 탐색을 막고, 기록 삭제 확인 중에는 기존과 같이 검색 입력의 Enter와 화살표를 소비한다. 확인 중에도 기존 내부 결과 행을 명시적으로 클릭하는 동작은 유지한다.

새 탐색 행을 클릭하면 필드와 현재 검색을 검증한 뒤 그 행을 실행 선택으로 기록한다. 준비 중인 새 탭 때문에 같은 URL의 방문 기록 결과가 목록에서 빠져도 이 선택은 유지한다. 그 뒤 사용자가 다른 결과를 선택하거나 검색어를 바꾸면 이전 실행은 거절한다. 생성 실패 때도 클릭한 새 탐색 행의 선택을 유지한다.

## 사용자 공간과 실패

명시적으로 연 주소는 `browser::open_search_url → open_saved_user_url`의 기존 사용자 탭 경로를 사용한다. 같은 주소의 재사용 가능한 내 공간 탭이 있으면 선택하고, 없으면 배경에서 새 탭을 준비한 뒤 검색 대상과 현재 선택을 재확인한다. 성공한 경우만 내 공간으로 전환하고 검색 화면을 닫는다. 다른 AI 작업의 상태나 revision은 바꾸지 않는다.

생성 실패나 준비 중 검색 대상 변경은 현재 검색과 선택을 보존한다. 같은 검색이 남아 있으면 실패를 알리고, 사용자가 바꾼 새 검색에는 이전 실패 안내를 덮어쓰지 않는다. 생성한 탭이 여전히 소유권 없는 자체 준비 탭일 때만 정리한다. 탭 생성 후 페이지의 HTTP 로딩 실패는 별도의 탐색 실패 안내로 처리한다. 준비가 시작된 뒤 취소됐다고 이미 발생할 수 있는 네트워크 요청까지 되돌렸다고 설명하지 않는다.

## 자원과 검증

추가 상태는 제한된 검색어, 잘림 여부와 세대, 실행 순간의 해석 결과다. 기존 네이티브 검색 행과 사용자 탭 생성 경로를 사용하며 새 웹 UI, worker, 타이머, 저장 파일과 추천 서비스는 없다. 명시적 탐색으로 연 Chromium 페이지의 메모리는 기존 사용자 탭과 같은 비용이며 전체 RAM 감소를 주장하지 않는다.

해석과 표시 순서, 세대와 잘림, 실행 경계는 상태 검사와 코드 호출 흐름으로 검증한다. 실제 AppKit 클릭과 IME, 새 탭 생성과 실패, AI 공간 선택 보존은 같은 최종 Naru 바이너리의 후속 로컬 CEF 검증이 필요하다. 실행한 검사와 미검증 범위는 [작업 기록](work-log.md)에 구분한다.
