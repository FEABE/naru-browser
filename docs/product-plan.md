# Naru 독립 브라우저 완성 계획

기준일: 2026-10-20. 개발 목표는 **Naru를 먼저 완성하고 Aside와 ego lite의 장점을 결합하는 것**이다. 완성한 Naru 화면과 기능을 같은 Rust·CEF·Chromium 구현으로 Preseller에 내장하는 순서는 유지하며 목표는 진행 중이다. 사용자는 Aside의 장점 중 **세로 탭·검색·북마크 등 일상 브라우저 사용성을 우선**하도록 선택했다.

2026-10-16 개발 방식 변경을 반영해 남은 기능을 합의한 범위에서 먼저 구현한다. 기능별로 전체 회귀 묶음을 반복하는 대신 통합 빌드가 준비되면 [독립 브라우저 E2E 체크리스트](ego-parity-e2e.md)의 14개 실제 사용 여정을 같은 앱 바이너리로 확인한다. 결함 수정 뒤에는 실패한 여정과 영향을 받는 범위를 확인하며, 이전 바이너리의 통과를 새 빌드의 결과로 옮기지 않는다.

완료 여부는 체크리스트의 `pending`, `pass`, `fail`, `blocked`와 실행 근거로 판단한다. 사용자 공간 보존, AI 중지와 인계, 실제 입력 대상, 데이터 보존과 자원 회수 같은 핵심 항목이 미완료면 독립 브라우저 완성을 선언하지 않는다. 아래 기능별 기록은 구현과 과거 검증의 이력이며 최종 E2E 통과표가 아니다. 기준은 2026-10-11 실제 앱 관찰과 Naru의 합의 범위다. 최신 ego lite의 모든 기능과 동등하다는 뜻은 아니다. 탭 복원과 페이지 확대는 사용자 보류를 유지한다.

같은 날 `c40bf03` 커밋과 푸시 후 기존 v17으로 파일 저장창 취소, 진행 중 취소와 부분 파일 제거, 불완전 응답의 내부 재시도 후 실패 표시를 추가 확인했다. 이 v17에는 사용자가 실패 항목에서 다시 받는 버튼이 없다. Finder 호출 안내는 확인했지만 실제 대상 선택은 미확인이다. 상세 범위는 [파일 UI 후속 실행](native-e2e-2026-10-20.md#같은-v17의-파일-ui-후속-실행)을 따른다.

[v18 상세 근거](native-e2e-2026-10-20.md#v18-수동-다시-받기)를 따른다. 전체 14개 여정의 완료가 아니다.

[파일 선택 계약과 실행 결과](file-selection.md)에 바이너리별 근거와 남은 E2E를 구분했다.

위치, 알림, 카메라와 마이크의 [사이트 권한 처리와 네이티브 UI](site-permissions.md)는 일반 권한의 프로필 저장과 미디어 요청의 허용 범위를 구분하고 원래 문서 및 제어권을 확인한다. 전체 최대 4개, 탭마다 1개 요청만 메모리에 보관한다. v22 후속 실제 실행에서 알림 취소, 허용과 초기화, 배경 AI 선택 보존, 인계와 문서 및 프레임 변경, 미디어 취소, 상한과 종료 정리를 확인했다.

[바이너리별 실행 범위](ego-parity-e2e.md)를 따르며 실제 OS 기기 허용과 미디어는 미검증이다.

사용자가 보류한 탭 복원과 확대는 그대로 유지한다. 폴더 선택과 화면 공유는 미지원이다. 파일 선택과 다운로드 저장창의 동시 요청, 늦은 완료 콜백의 모든 경합과 OOPIF 파일 선택은 미검증이다. 기존 북마크 삭제나 긴 탭 목록과 IME의 미실행 검증을 새 기능으로 세지 않는다. 이 후보들을 비교 앱에서 실측한 기능 차이나 제품 전체의 구현 완료로 표시하지 않는다.

## 텍스트·키 입력의 임시 페이지 포커스 준비

후속 구현은 정확한 session의 focus emulation enable ACK 뒤 원래 대상의 준비를 새로 수행한다. 입력을 한 번 요청하고 disable ACK 뒤 값을 읽거나 입력 대상 관찰을 소비하며, 사용자 창의 포커스를 옮기는 호출은 추가하지 않는다. 일반 입력칸의 fill은 입력 종류를 먼저 분류하고 다른 대상으로 전달된 이벤트 증거를 최종 값 일치보다 우선 실패로 처리한다. [포커스 준비 계약](focus-input.md)에 취소·늦은 응답·정리와 페이지 visibility 부작용을 기록한다. 첫 페이지 focus 전환을 준비 앞으로 옮기는 보완이며 지연된 모든 스크립트와 사람 입력의 경합을 막는 기능은 아니다. 실제 CEF의 입력과 사용자 화면 보존은 E2E에서 확인한다.

## 교차 출처 프레임의 읽기와 입력

후속 `read-page TAB`은 현재 탭의 루트와 하위 문서를 순차 읽어 한 응답으로 돌려준다. 문서 시도는 최대 16개이며 본문 12,000 UTF-16 단위·요소 120개·순회 10,000회·열린 root 64개·옵션 240개·로컬 iframe 메타데이터 16개를 공유한다. 본문을 중복 순회하지 않고, 읽지 않은 문서는 사유와 함께 구분한다. 여러 프레임의 참조는 마지막 정리 ACK 뒤에 한 묶음으로 게시하며 부분 실패에서 일부 참조만 성공처럼 반환하지 않는다. [통합 읽기 계약](page-read.md)에 범위와 실제 앱에서 확인할 항목을 기록한다.

2026-10-18 `read-frame TAB FRAME`을 본문 전용 조회에서 문서에 결합한 입력 참조까지 확장했다. 현재 프레임을 정확한 session과 고유 context로 읽고 `click`, `hover`, `fill`, `insert`, `press`, `check`, `select`를 연결한다. 기존 `read`의 다중 문서 결과와는 별도 명령이며 `supportedActions`와 `pointerActionsSupported:true`, `atomic:false`로 범위를 알린다.

기존 fill을 명시적인 `contenteditable` 영역으로 확장했다. 빈 속성과 plaintext-only도 읽으며 전체 내용을 일반 텍스트로 바꾸고 취소 가능한 beforeinput을 먼저 전달한다. 같은 삽입 노드의 결과를 확인하고 페이지 핸들러가 바꾸거나 대상을 교체하면 성공으로 단정하지 않는다. 서식과 편집기 내부 모델, Selection과 undo를 보존하는 기능은 아니다. [입력 계약](contenteditable-control.md)에 대상 선택, 이벤트, 자원 상한과 검증 경계를 기록한다. 최신 Naru 앱 통합과 실제 외부 편집기 호환성은 남는다.

## 검색 키 처리와 대기 요청 상한

검색 입력에 포커스가 있을 때만 Enter와 화살표로 결과를 조작한다. 삭제 확인 중에는 입력 필드에서 결과를 열거나 선택을 옮기지 않고, 버튼 포커스의 키는 AppKit에 전달한다. 소켓 worker가 시간 초과된 뒤에도 미실행 UI 요청의 자리를 유지하도록 서버별 payload 상한 16개를 추가했다. 실제 네이티브 키 입력과 장시간 CEF UI 정지 검증, 전체 RAM 측정은 남는다. 이 변경과 커밋 검증은 작업 기록에 구분한다.

## 배경 탭 실패 표시

선택하지 않은 탭의 탐색 실패와 렌더러 종료도 기존 사이드바 행에 경고 아이콘으로 표시한다. 실패 상태만 바뀌어도 행을 갱신하고, 툴팁과 접근성 설명에는 AI 작업과 로딩, 음소거 상태를 함께 남긴다. 복구 탐색 중에는 기존 탐색 상태가 판단한 failure 값에 따라 경고를 해제한다. 자동 선택이나 재시도는 하지 않으며 실제 Naru의 배경 실패 화면과 접근성 검증은 남는다.

## 체크박스와 라디오 상태 지정 소스

`check TAB REF true|false`를 추가해 AI가 원하는 선택 상태를 지정하도록 했다. 이미 같은 상태라면 클릭하지 않고, 한 번 클릭한 뒤 페이지가 취소하거나 상태를 바꾸었는지 확인한다. `read`는 혼합 상태를 표시하며 혼합 체크박스와 라디오 해제, 사용자 정의 ARIA 컨트롤은 거절한다. CLI 오류는 클릭 시도 여부를 보존하고 기존 작업 제어권과 참조 만료를 따른다. [계약과 검증 경계](check-control.md)에 기록했다.

모의 DOM 70개와 독립 ego lite의 격리된 Chromium 환경 24개 시나리오를 통과했다. 최종 Chromium 검사는 페이지 단위 포커스 에뮬레이션을 사용했다. 기존 Naru 앱은 교체하지 않았으며 실제 CEF 요청 연결, macOS 입력, 외부 사이트와 장시간 사용 검증은 남는다. 이 기능만으로 AI 제어 호환성이나 독립 브라우저 완성을 선언하지 않는다.

## 페이지 우클릭 메뉴와 제어권 보호 소스

후속 소스는 HTTP(S) 링크의 우클릭 메뉴에 `링크 주소를 새 탭에서 열기`를 추가한다. 원래 공간의 배경 탭으로 열고 현재 선택을 유지한다. 활성 작업의 직접 개입은 해당 작업만 인계하며 새 탭은 AI 소유로 만들지 않는다. 승인된 URL을 고정하고 큐와 생성 완료 시 원본 탭, 공간과 소유권을 재검사한다. 기존 생성 경로에 따라 referrer와 opener 연결 없이 주소를 새로 탐색하며, 링크의 JavaScript나 download 속성을 실행하는 기능은 아니다. 최신 실제 메뉴와 네트워크 요청 검증은 남아 있다.

2026-10-15에 CEF 기본 우클릭 메뉴의 명령 직전 검사를 추가했다. 메뉴를 연 뒤 선택, 문서와 프레임, 작업 소유권이나 revision이 바뀌면 이전 명령을 거절한다. 정상 사용자 메뉴는 유지하며 활성 작업의 직접 개입은 기존 handoff를 사용한다. 모든 프레임 탐색에서 메뉴를 무효화하므로 다른 iframe이 이동해도 메뉴를 다시 열어야 할 수 있다. 고정 엔진의 명령과 종료 알림 순서는 원문으로 확인했고, [계약과 검증 경계](context-menu-control.md)에 기록했다. 최신 소스의 실제 네이티브 메뉴 검증은 남아 있다.

## 같은 공간의 탭 순서 변경 소스

후속 드래그 정렬은 같은 공간의 탭을 마우스로 옮기고 삽입선을 표시한다. 배경 탭을 끌어도 현재 선택과 AI 작업 상태를 유지한다. 작은 마우스 이동에서 클릭이 사라지는 AppKit 검사 결과에 따라 6pt부터 시작하는 제스처를 사용한다. 분리된 네이티브 이벤트 검사와 최종 Naru 앱 검증은 구분하며 실제 CEF 화면, 입력기, 장시간 사용은 남아 있다.

긴 목록의 가장자리 자동 스크롤도 소스에 연결했다. 포인터를 멈춰도 반복 이동하고 중앙과 문서 끝에서는 타이머를 해제하며 드롭을 유지한다. 자체 세로 이동만 허용하고 공간과 선택, 전체 탭 순서와 배치 변경은 이전 대상을 무효화한다. 자동 스크롤 중에만 네이티브 타이머 하나를 사용한다. 독립 AppKit의 좌표와 타이머 수명 검사 결과를 실제 Naru 드래그나 RAM 측정으로 확대하지 않는다.

2026-10-15 보기 메뉴의 현재 탭 위로 이동·아래로 이동을 추가했다. 같은 공간 안에서 선택한 탭과 실제 방향별 이웃의 순서만 바꾸며 선택한 페이지와 AI 제어권을 유지한다. 공간별 표시 순서는 사이드바, 번호 단축키와 이전·다음 탭에서 함께 사용한다. 새 탭과 공간 사이에서 이동한 탭은 목적지 마지막에 놓이며 재시작 복원과 공간 간 드래그는 추가하지 않았다. [표시 순서와 수명 계약](tab-order.md), 소스 검사와 미실행 앱 검증은 작업 기록에서 구분한다.

## UI 방향과 1차 적용: Aside의 구성과 토스의 시각 표현

2026-10-13 사용자는 기본 기능을 어느 정도 완성한 뒤 Aside 형식의 화면에 토스 디자인을 참고하는 방향을 제안했다. 탐색 복구 검증을 정리한 뒤 이 방향의 1차 UI를 적용하고 최종 aside-toss-v2에서 로컬 검증했다. 화면 구성은 Aside, 여백·글자·버튼·상태 표현은 토스의 공개 디자인 자료, 사용자·AI 공간과 CLI 동작은 기존 Naru 모델을 따른다. 아래 표는 전체 설계 방향이며 실제 적용·검증 범위는 별도로 기록한다.

UI용 웹 renderer나 TDS 실행 패키지는 추가하지 않으며 시스템 폰트·기존 네이티브 뷰 재사용을 유지한다.

적용 순서는 공통 색·글자·간격과 한 화면의 시안 → 사이드바 → 주소줄·새 탭·검색 → 복구·다운로드·AI 상태다. 시각 확인과 함께 작은 창, 키보드 포커스, 긴 한글 제목, 밝은/어두운 환경, 사용자 선택 보존을 검사한다. 디자인 변경의 메모리 비용은 같은 조건에서 따로 확인하고 예상 절감량을 성과로 쓰지 않는다.

1차 적용은 `src/control_panel.rs`의 탐색 구조와 공통 시각 표현에 한정한다. 상단에 40pt 검색과 공간 전환, 현재 공간 제목·38pt 간격의 세로 탭을 배치하고 하단은 36pt 북마크·다운로드와 40pt 파란 새 탭 버튼으로 나눴다. 도구 모음은 56pt, 주소 영역은 36pt이며 주소·탭 제목은 13pt 시스템 폰트를 쓴다. 중립색 표면·파란 선택 배경·중간 굵기의 글자로 위계를 맞췄고 sidebar 216pt·접힘 rail 76pt, 기존 클릭·주소 초안·AI 제어권 로직은 유지한다. 고정 SurfaceView 3개를 추가하고 기존 탭 행을 재사용하며 UI용 웹 renderer를 추가하지 않는다.

최종 aside-toss-v2 앱 SHA-256은 `c00666472cca6ad069f511050cad84d9a0f11dcc08f673edea46950d52da64ff`다. Rust 190개·전체 타깃 Cargo 검사·format·release가 통과했고 기존 test 전용 dead_code 경고 2개는 남는다. 같은 바이너리의 select 10개·tasks 6개·spaces 10개·single_window 6개, 총 32개 로컬 CEF 회귀가 모두 exit 0·빈 stderr로 통과했으며 `cleanupVerified: true`다. 근거는 `artifacts/aside-toss-v2-final-rust-tests.log`, `artifacts/aside-toss-v2-final-check.log`, `artifacts/aside-toss-v2-final-fmt.log`, `artifacts/aside-toss-v2-build.log`, `artifacts/aside-toss-v2-suite.json`과 `artifacts/aside-toss-v2-suite-state.json`이다. 이전 recovery-v2의 51개 실행 증거를 이 UI 바이너리의 검사 수에 합산하지 않는다.

네이티브 화면에서 새 탭 아이콘과 글자가 한 그룹으로 중앙 정렬되고 클릭 직후 주소 입력에 포커스가 가는 것을 확인했다. 배경 빈 탭 행을 닫은 뒤 주소의 한글 초안에 이어 쓰기, 한글 붙여넣기 검색과 Enter로 원래 탭 복귀, 긴 한글 제목의 말줄임과 전체 접근성 도움말, 접힌 사이드바의 선택·닫기 분리와 자체 HTTP 탭 닫기 후 원래 탭 복귀도 확인했다. 빈 AI 공간 A의 중지 버튼은 A만 paused revision 2로 바꾸고 B는 active revision 1을 유지했으며 공간 카드에 사용자·실행·중지 상태가 구분됐다. 빈 다운로드 화면은 사이드바·도구 모음을 숨기고 닫기 버튼에 포커스를 주며 Esc로 복귀했다. 근거는 `artifacts/aside-toss-v2-native.json`이다. 실제 페이지 동작 도중 AI 중지를 검증한 결과는 아니다.

최종 v2의 첫 HTTP 두 번은 commit·문서 사용 가능 전 각각 5,041ms·5,045ms에 시간 초과였다. 앱 스택 825개 표본에서 키체인 API 응답 대기를 확인했고, 이후 재빌드 없이 같은 바이너리의 실제 HTTP가 완료됐다. OS 대기가 해소된 정확한 원인은 추정하지 않으며 재빌드 간 키체인 권한 유지가 해결됐다고 표시하지 않는다. 최초 대기와 후속 완료는 `artifacts/aside-toss-v2-native.json`, `artifacts/aside-toss-v2-http-recovered.json`에 구분해 남긴다.

이전 v1은 1602×1104픽셀로 좁힌 실제 화면과 북마크의 빈 목록·원본 탭을 닫은 뒤 검색 입력 포커스를 확인했다. 새 탭 아이콘과 글자의 정렬 문제를 발견해 v2에서 수정했으며 v1에는 CEF 회귀 32개를 실행하지 않았다. 근거는 `artifacts/aside-toss-v1-validation.json`이다. 최종 v2의 크기 변경 시도는 실제 창 크기를 바꾸지 못했다. 같은 배치의 최소 크기 단위 검사는 통과했지만 최종 v2의 실제 최소 창 성공으로 기록하지 않는다.

교체 전 앱 PID 98551은 exit 0으로 종료했고 최신 앱 PID 4240 하나를 남겼다. 자체 fixture PID 93300도 exit 0으로 종료했다. 원래 사용자 탭 1만 선택된 상태와 다운로드·권한·저장·대기·캡처·탭 생성 예약 0을 확인했으며 사용자 프로필은 보존했다. v2 빌드 중간 파일 4,332개·2.5GiB를 정리했다. 근거는 `artifacts/aside-toss-v2-final-state.json`과 `artifacts/aside-toss-v2-validation.json`이다.

한글 입력은 붙여넣기이며 IME 조합은 미검증이다. 최종 최소 창·다크 모드·모든 버튼의 키보드 이동·외부 사이트·저장/권한 UI·RAM 비교도 확인하지 않았다. 새 탭 화면·검색·북마크 내부 배치 등 전체 디자인 방향, 독립 브라우저 전체와 Preseller 내장은 계속 미완료로 구분한다.

## 네이티브 새 탭 시작 화면

2026-10-13, Aside 구성·토스 표현의 후속으로 중앙 주소·Google 검색 입력과 북마크 진입을 구현했다. 앱이 직접 만든 실제 빈 탭에만 표시하며 CLI 탭과 내용이 있는 빈 주소 팝업은 기존 CEF 화면을 유지한다. 같은 탭·공간·탐색 세대에서 배경 갱신과 오버레이 왕복은 초안을 보존하고 대상 변경은 초기화한다. 유효한 제출만 기존 탐색·AI 인계 경로로 전달한다. 별도 웹 UI나 저장소는 추가하지 않았다.

첫 빌드의 실제 검사에서 빈 Enter의 포커스 이동과 AI 인계 후 주소가 비는 문제를 찾아 수정했다. 최종 v2는 Rust 194개·전체 타깃·format·release를 통과했으며, 두 오류 수정과 배경 탭 닫기·AI HTTP·CLI 읽기·오버레이 왕복·AI별 인계를 네이티브 화면에서 확인했다. 사용자가 추가 검증을 허용한 뒤 같은 바이너리의 사용자 중앙 Enter HTTP·빈 주소 팝업 입력·CLI reload 초안 초기화·페이지 변경 시 시작 화면 해제·사이드바 접기/펼치기도 확인했다. 로컬 CEF select 10개·tasks 6개·spaces 10개·single_window 6개, 총 32개가 exit 0·빈 stderr·cleanup true로 통과했다. 자체 탭·작업·서버를 정리하고 원래 사용자 탭 하나를 보존했다. 이전 빌드의 성공을 최종 바이너리 검사 수에 합산하지 않는다. 계약과 실행 경계는 [시작 화면 설계](start-page-design.md), 최신 결과와 정리는 [작업 기록](work-log.md)에 남긴다. 검색·북마크 내부 배치, 실제 최소 창·IME·다크 모드·외부 서비스·RAM 비교와 독립 브라우저 전체 완성은 계속 후속 범위다.

## 개발 순서와 완료를 판단할 증거

후속 `ui-focus-v3`는 편집 중 사이드바 북마크·검색·다운로드로 전환할 때 입력이 사라지는 순서를 보완했다. 실제 네이티브 왕복의 초안 보존과 AI A만 인계되는 경계를 확인했고 Rust 194개·전체 타깃·format·release가 통과했다. 사용자 키체인 승인 후 같은 최종 바이너리의 HTTP·팝업 실제 입력과 로컬 CEF 회귀 32개도 통과했다. 원래 사용자 탭 하나를 보존하고 자체 작업·서버·대기 자원을 정리했다. 해당 빌드에서는 주소창에서 중앙 입력으로 Tab 이동, 사이드바 펼침 직후 모서리 표시, 실제 최소 창이 후속 범위로 남았다. 구체적인 결과·프로세스 정리는 작업 기록을 따른다.

### 키보드 이동과 사이드바 후속 진단

`native-focus-v1`은 숨긴 `RenderWidgetHostViewCocoa`가 주소창의 다음, 중앙 입력의 이전 유효 키 뷰로 반환되고 실제 first responder가 되는 경로를 확인했다. 같은 Tab 이벤트에 `OnGotFocus`만 관찰됐고 `OnSetFocus` 거절 경로는 호출되지 않았다. 원래 AppKit 이벤트 전달을 마친 뒤 실제 숨긴 CEF에 포커스가 남은 경우만 보정하는 소스를 추가했다. 버튼을 제외한 수동 순서는 만들지 않고 AppKit의 유효 후보 순서를 사용한다. 같은 창, 가시성, 현재 responder를 다시 확인한 뒤 이동하며 순환과 후보 512개 상한에서 중단한다.

`native-focus-v2`는 Rust 194개, 전체 타깃 검사, format, release 빌드를 통과했다. `artifacts/native-focus-v2-native.json`에서 진단 ON은 주소창 Tab→중앙, 중앙 ShiftTab→주소창 두 방향을 확인했다. 진단 OFF는 주소창과 중앙 입력 사이 Tab, ShiftTab 네 방향을 확인했다. 이 중간 빌드에는 HTTP와 로컬 CEF 회귀 실행 결과가 없다. 앞선 ui-focus-v3의 네이티브 초안 보존과 CEF 32개 결과는 그 바이너리의 이력으로 유지한다.

최종 `native-focus-v3`는 Rust 194개, 전체 타깃 검사, format, release 빌드와 같은 바이너리의 로컬 CEF 32개(select 10, tasks 6, spaces 10, single_window 6)를 통과했다. 모든 suite가 exit 0, 빈 stderr였고 cleanup을 확인했다. 진단 OFF에서 주소창과 중앙 입력 사이 Tab, ShiftTab 네 방향과 실제 입력, 북마크·검색·다운로드 왕복의 초안 보존을 확인했다. B의 배경 HTTP 탐색 동안 A 선택과 초안을 유지했다. A 공간의 Tab과 입력은 A/B 모두 active revision 1을 유지했고 유효 HTTP Enter에서만 A paused revision 2, B active revision 1이 됐다. 웹 입력에서 Tab으로 버튼 이동 후 Return으로 내용이 있는 `about:blank` 팝업을 열었으며 팝업의 실제 입력값과 CLI read가 일치했다. 추가 키체인 질문 없이 HTTP를 완료했지만 빌드 간 권한 유지의 해결은 미입증이다. 자체 검증 작업과 서버를 종료하고 원래 사용자 탭 하나와 최종 앱을 보존했다. 근거는 `artifacts/native-focus-v3-native.json`, `artifacts/native-focus-v3-suite.json`, `artifacts/native-focus-v3-suite-state.json`이다.

사이드바 모서리 잘림은 native-focus-v1의 재그리기 후보로 해결되지 않았다. v2도 좌표 진단 ON에서만 정상이었고 OFF에서 다시 잘려, 조회가 현상을 가리는 영향이 확인됐다. view와 model의 음수 좌표 근거는 없으며 조회에 따른 동기화와 시간 경과 중 어떤 영향인지는 미확정이다. native-focus-v3의 조건부 `displayIfNeeded` 적용 뒤 초기 검사에서도 잘림이 재현됐다. 이후 같은 실행에서 접기·펼치기 두 차례, 같은 바이너리 재실행과 독립 CUA 캡처는 정상이었다. 초기 실패 관찰은 유지하며 재현 조건을 확인하지 못해 해결로 판정하지 않는다.

후속 `surface-probe-v1`은 기본 OFF인 getter 비교 진단만 추가했고 format과 release 빌드를 통과했다. 기본 모드 한 주기의 표시와 로그 0건, 같은 바이너리의 `noop` 토글 18회와 로그 1~16 상한을 확인했다. 토글마다 접근성 상태를 확인했고 마지막 화면은 정상이었지만 매회 이미지 판독은 아니다. 재현 대조군이 없어 getter별 실험과 효과 판정은 하지 않았다. 기본 모드의 새 탭 Tab 입력, 북마크 왕복 초안 보존, 중앙 HTTP Enter와 CLI 읽기도 확인했다. 진단만 추가한 이번 빌드에서는 Rust 검사, 전체 CEF 32개 회귀와 모의 DOM 검사를 추가 실행하지 않았으며 이전 194개와 32개를 이번 성과로 합산하지 않는다. 최초 종료는 watchdog exit 2였고 이후 `noop`과 기본 모드 HTTP 검증 후 종료는 exit 0이었다. 종료 차이의 원인은 미확정이다. 자체 서버와 검사 탭을 정리하고 진단 OFF 앱과 원래 사용자 탭 하나를 남겼다.

포커스 진단은 기본 OFF, 최대 128줄이고 표면 좌표 진단은 기본 OFF, 최대 32표본이다. 새 getter 비교 진단도 기본 OFF, 최대 16회이며 새 캐시, 타이머, 웹 UI는 없다. 입력값과 URL은 출력하지 않는다. FKA 활성 설정, 실제 IME 조합, 최소 창, 다크 모드, 외부 서비스와 RAM 비교는 미검증이다. 소스 계약과 버전별 경계는 [시작 화면 설계](start-page-design.md)에 기록한다.

## 세로 탭 행 개선 진행

숫자 단축키 `⌘1`~`⌘8`은 현재 표시 공간의 사이드바 순서, `⌘9`는 마지막 탭을 선택하도록 추가했다. 없는 번호와 목록 화면·공간 둘러보기가 닫힌 상태의 같은 탭 선택은 입력을 유지한다. 실제 공간 소속과 탭 생존을 다시 확인해 선택에 성공한 경우에만 목록 화면을 닫고, AI 작업의 제어권은 유지한다. 새 캐시나 웹 renderer는 없다. 최종 v3는 Rust 198개·전체 타깃·format·release와 네이티브 숫자 선택·입력 보존·AI 상태 보존을 확인했다. 검색·북마크 왕복에서 상단 주소 초안 보호도 보완했다. HTTP·로컬 CEF는 키체인 대기로 미완료이며 사용자의 추가 승인 요청 중단 지시에 따라 검사 자원을 정리했다. 반복 승인 문제는 해결되지 않았다. [작업 기록](work-log.md)에 중간 실패·최종 결과·미검증 범위를 구분한다.

2026-10-13에 `src/control_panel.rs`의 각 탭 행에 독립된 닫기 버튼을 추가했다. 펼친 사이드바에서는 제목·상태 아이콘·닫기를 표시하고, 접힌 사이드바의 폭은 76포인트로 두어 선택과 닫기 영역을 나눴다. 제목·URL·로딩·선택 상태가 바뀌어도 탭 ID와 공간이 같으면 기존 AppKit 행을 재사용한다. 닫힌 탭이나 다른 공간으로 이동한 행은 제거하며 제목·URL 툴팁과 접근성 라벨은 현재 값으로 갱신한다. 접힌 사이드바의 실제 화면에서 선택과 닫기 영역이 분리된 것을 확인했다. 빈 탭의 행 닫기는 동작했으며 좁은 전체 창은 별도 검증이 남았다.

행 동작은 현재 버튼 포인터, 탭 ID, 표시 공간과 overlay 상태를 확인한다. 닫기 직전에는 `src/browser.rs`가 실제 공간 소속과 탭 존재를 다시 검사하므로, 화면 갱신 전에 adopt/release된 탭을 이전 행으로 닫거나 그 작업을 중지하지 않는다. AI 공간의 유효한 닫기는 기존 사용자 개입 경로를 따른다. 선택하지 않은 행을 닫을 때 현재 주소 초안을 보존하며, 같은 작업의 handoff가 현재 탭의 탐색 세대를 한 번 증가시키는 경우에만 초안의 세대를 맞춘다. 같은 탭·공간·URL, 정확히 한 세대 증가, AI 제어 해제와 정상 렌더러 조건을 확인하고 호출 뒤 예외 상태를 지운다. 실제 탐색·같은 URL 새로 고침·선택 변경을 일반적으로 무시하는 보호는 아니다.

Rust 단위 검사 178개, 전체 타깃 Cargo 검사와 format 검사를 통과했다. 추가 검사는 접힌/펼친 행의 선택·닫기 영역 분리, 이동·종료·overlay로 무효화된 행 거절, 실제 공간 상태를 쓰는 닫기 가드, 한 번의 handoff에만 주소 초안을 보존하는 조건을 확인한다. 근거는 `artifacts/tab-rows-v1-rust-tests.log`, `artifacts/tab-rows-v1-check.log`, `artifacts/tab-rows-v1-fmt.log`다. release 빌드가 통과했고 같은 바이너리의 빈 탭에서 펼친/접힌 배경 행 닫기 후 선택·주소 초안·입력 포커스 보존과 선택한 행 닫기를 확인했다. AI 형제 탭 닫기에서는 해당 작업만 paused revision 2로 바뀌고 다른 작업은 active revision 1을 유지했다. 주소에 이어 쓰기도 성공했다. 근거는 `artifacts/tab-rows-v1-native.json`과 `-after-ai-close.json`이다. 첫 HTTP는 commit 전 WAIT_TIMEOUT으로 사용자 확인을 기다렸으며, 승인 후 같은 tab-rows-v1 바이너리(SHA-256 `2a5b4ae280cf0d195e9e388279ba58174a6a7d0147cc06310e36ef7923d1c7bb`, PID 56917)의 로컬 HTTP에서 commit·문서 사용 가능·메인 로드 완료를 확인했다. 배경 탭 행 닫기의 beforeunload에서 Cancel은 탭을 유지하고 OK는 해당 탭을 닫았다. 두 경로 모두 원래 사용자 탭 1의 선택과 주소 초안을 보존했고 재포커스 없이 이어 쓰기에 성공했다. 같은 바이너리의 select 10개·tasks 6개·spaces 10개·single_window 6개, 총 32개 CEF 회귀도 exit 0·빈 stderr로 통과했다. 정리 뒤 원래 user 빈 탭 1만 남았고 다운로드·권한·저장·wait·캡처·탭 생성 대기는 모두 0개였다. 네이티브 ⌘Q로 해당 앱의 exit 0을 확인했다. 근거는 `artifacts/tab-rows-v1-approved-native.json`, `artifacts/tab-rows-v1-suite.json`, `artifacts/tab-rows-v1-suite-state.json`이다. 새 검색 별칭 소스의 적용·검증 결과와 구분한다. 새 모의 DOM·외부 사이트 검사나 메모리 절감 측정의 성공으로 합산하지 않는다.

## 새 탭 검색과 개발 서명 후속

이전 tab-rows-v1의 통합 검색에서 표시 제목 “새 탭”을 “새”로 검색하면 결과가 없고 원래 URL about로 검색하면 결과가 나오는 문제를 확인했다. `src/tab_search.rs::display_title`을 검색 결과·사이드바에 공유하고 원래 제목·URL·공간 매칭에 표시 별칭을 추가했다. 일반 제목을 중복 복사하지 않으며 기존 입력·결과·필드 상한을 유지한다. 독립 검색 모듈 6개에 이어 같은 소스 전체 Rust 179개·전체 타깃 Cargo 검사·format·diff 검사가 통과했다. 후속 tab-search-label-v1 release 빌드는 exit 0이며 앱 SHA-256은 `9a24e9181f909c07482cf26f610676be39b3b618990525b37d65faab3ac6eb88`, 최초 실행의 메인 PID는 68589다. 실제 검색창에 “새”와 “새 탭”을 각각 붙여넣으면 “새 탭 / 내 공간 / about:blank” 결과 하나가 표시됐고 Return으로 원래 사용자 탭 1을 선택했다. 네이티브 붙여넣기 검사이며 IME 조합 성공으로 확대하지 않는다. 독립 검색 검사의 원본은 `artifacts/tab-search-label-v1-tests.validation.json`, 최종 빌드·네이티브 결과는 `artifacts/tab-search-label-v1-validation.json`이다.

최종 검색 바이너리의 첫 로컬 HTTP 탭 2는 5초 대기를 요청한 뒤 5,039ms에 WAIT_TIMEOUT이었으며 commit·문서 사용 가능은 false였다. 당시 새 SecurityAgent PID 68597을 확인하고 사용자 승인을 요청했으며 최초 실패 기록은 그대로 보존했다. 사용자 승인 후 재빌드 없이 같은 SHA와 PID 68589에서 기존 HTTP 탭의 commit·문서 사용 가능·메인 로드 완료를 확인했다. 실제 배경 행 닫기의 beforeunload에서 Cancel은 탭을 유지하고 OK는 닫았다. 두 경로 모두 원래 user 탭 1의 선택과 주소 초안을 보존했고 재포커스 없이 이어 썼다. `artifacts/tab-search-label-v1-approved-native.json`은 이 최종 바이너리의 별도 실행 결과다.

같은 최종 바이너리의 select 10개·tasks 6개·spaces 10개·single_window 6개, 총 32개가 모두 exit 0·빈 stderr로 통과했고 `cleanupVerified: true`였다. 회귀 작업 9개는 모두 finished로 정리됐으며 원래 user 빈 탭 1과 다운로드·권한·저장·wait·캡처·탭 생성 대기 0개를 확인했다. 근거는 `artifacts/tab-search-label-v1-suite.json`, `artifacts/tab-search-label-v1-suite-state.json`, `artifacts/tab-search-label-v1-post-suite-state.json`이다. 이전 tab-rows-v1의 통과 결과와 구분한다.

네이티브 ⌘Q로 PID 68589의 exit 0을 확인한 뒤 같은 SHA와 프로필로 재시작했다. 재시작 PID 71159에서 추가 승인 질문 없이 로컬 HTTP의 commit·문서 사용 가능·메인 로드 완료를 확인했고 SecurityAgent는 관찰되지 않았다. 자체 HTTP 탭을 제거하고 fixture를 정상 종료(exit 0)한 뒤 원래 user 빈 탭 1만 선택됐으며 작업 목록과 모든 대기는 0개였다. 이번 후속 검증에는 새 빌드가 없었다. `artifacts/tab-search-label-v1-restart-http.json`, `artifacts/tab-search-label-v1-final-state.json`, `artifacts/tab-search-label-v1-final-validation.json`에 기록했다. 기본 ad hoc 서명의 동일 바이너리 재시작을 확인한 범위이며, 실제 인증서 서명이나 변경 빌드 사이 권한 유지 성공으로 확대하지 않는다. 외부 사이트·IME 조합·좁은 창·키보드만으로 행 닫기·메모리 절감·Preseller 내장은 남아 있다.

기존 tab-rows-v1에서는 CLI로 자체 현재 빈 탭을 닫은 뒤 통합 검색 입력, 자체 배경 탭을 닫은 뒤 북마크 검색 입력과 다운로드 닫기 버튼 포커스 유지도 추가 확인했다. 실제 입력을 이어 쓰고 Space로 패널을 닫았다. 키보드만으로 탭 닫기에 도달하는 흐름과 좁은 전체 창은 아직 검증하지 못했다. 이 추가 근거는 `artifacts/tab-rows-v1-followup.json`이며 새 검색 소스의 네이티브 성공으로 세지 않는다.

HTTP 대기 중 동일 앱을 1초 샘플링해 작업 스레드의 `SecItemCopyMatching → SecKeychainItemCopyContent → SecurityServer::ClientSession::decrypt → mach_msg` 응답 대기를 확인했다. 키체인 항목 내용이나 보안 창은 읽지 않았으며 정확한 항목·창 상태와 전체 네트워크 대기의 인과는 미확정이다. 반복 빌드의 기존 ad hoc 서명은 현재 번들의 공개 메타데이터에서 cdhash 기반 designated requirement를 확인했다. 후속 스크립트는 `--signing-identity`와 `NARU_CODESIGN_IDENTITY`로 선택한 서명자를 명시할 수 있게 했으며 기본 ad hoc과 기존 보호 절차를 유지한다. 이 옵션의 준비를 실제 안정 서명·권한 유지 또는 배포 완료로 표시하지 않는다.

### 개발 빌드의 실행 분리

2026-10-15에는 반복 키체인 입력을 요구하지 않도록 `scripts/dev.sh`의 기본값을 빌드만 수행하는 방식으로 바꿨다. 실행은 명시적 `--run`에서만 허용한다. 실행 모드의 서명자가 미지정, 빈 값, ad hoc 값 `-`이면 다운로드나 Cargo 호출 전에 중단한다. 빌드 전용 모드에서는 브라우저 인수를 조용히 버리지 않고 거절하며, 서로 충돌하는 실행 옵션도 거절한다. 기존 번들 검증, 교체, 빌드 중간물 정리는 유지한다. 새 저장소나 런타임 구성요소는 없다.

이는 자동 실행으로 새 승인을 반복 요청하던 경로의 예방 조치다. 실제 인증서 생성이나 서명자 선택, 키체인 권한 변경, HTTP 성공을 뜻하지 않는다. 안정적인 서명으로 변경 빌드 사이 권한을 유지하는 검사와 numbered-tabs-v3의 HTTP, 로컬 CEF 검사는 남아 있다. 이번 스크립트 검증과 실제 앱 실행 여부는 [작업 기록](work-log.md)을 따른다.

## 다운로드에서 관련 탭 확인

2026-10-15 파일 카드의 접수 탭 보기와 권한 카드의 요청 탭 보기를 소스로 연결했다. 사용자의 명시적 동작만 기존 공간과 탭을 선택하며 AI 제어권, 권한 결정과 파일 수명을 유지한다. 파일은 접수 당시 문서와 소유권, 권한은 현재 대기 token과 기존 provenance를 검증한다. 새 문서나 제어권으로 대체하지 않는다. 중지된 AI 공간의 출처도 실제 작업 이름과 탭 번호를 남긴다.

별도 저장소나 웹 UI 없이 기존 24개 파일, 4개 권한 행에 버튼을 재사용한다. 파일의 최초 링크 클릭 문서 추적이나 CEF가 전달하기 전 숨긴 권한 자동 알림은 구현하지 않았다. Rust 단위 245개와 전체 타깃, CLI 구성의 컴파일 검사를 통과했다. 실제 앱의 배경 공간 이동, 권한 전달, 초안과 키보드 검증은 남는다. [상세 계약](downloads-design.md#다운로드와-권한-카드에서-관련-탭-보기)과 작업 기록에서 소스 검사와 실제 앱 증거를 구분한다.

## 현재 사이트의 다운로드 설정 초기화

다운로드 허용은 사이트 설정에 저장되지만 되돌리는 UI가 없었다. 2026-10-15 다운로드 목록에 고정 카드 하나를 추가해 현재 main frame의 실제 HTTP(S) origin과 적용 설정을 조회하도록 연결했다. 허용 상태일 때 DEFAULT로 저장 예외를 초기화하고 ASK 또는 BLOCK 재조회에 성공한 경우만 확인 결과를 표시한다. 공유 프로필의 같은 사이트에 적용되며 사용자와 AI 탭의 선택, 작업 revision을 바꾸지 않는다.

설치 CEF와 Chromium의 고정 원문을 확인해 저장된 설정, 열린 문서의 캐시와 대기 요청을 구분했다. 현재 구현은 전체 승인 사이트 목록이나 모든 기존 문서의 즉시 권한 철회가 아니다. 네이티브 UI에 페이지 다시 열기, 대기 취소 가능과 진행 파일 보존을 명시한다. [설계와 원문 근거](download-site-settings.md)에 범위와 실행 검증 항목을 기록했다. 새 회귀 8개를 포함한 Rust 단위 239개와 전체 타깃, CLI 구성의 컴파일 검사를 통과했다. 앱 번들 반영과 실제 프로필, CEF, AppKit 검증은 남는다.

## 방문 기록과 검색 확장

2026-10-15 사용자가 승인한 내 공간만 기록 정책을 구현했다. 내 공간의 소유되지 않은 탭에서 실제 문서와 최종 HTTP(S) 주소를 확인하고 URL, 제목, 최근 방문 시각을 별도 JSON에 저장한다. 최근 30일, 최대 1,000개와 2MiB, 과거 목록 백업 없음이 상한이다. 통합 검색은 기존 탭, 북마크 다음 기록을 표시하며 전용 모드로 최신 기록만 볼 수도 있다. 전체 삭제 확인과 취소, 처리 중과 실패 안내를 함께 연결했다.

단일 worker, 최대 64개와 256KiB의 합쳐진 대기, 삭제 세대, 늦은 제목과 AI 문서 제외, 생성 실패 탭의 미기록을 구현했다. 삭제 당시 열린 문서는 새 전체 탐색 전까지 SPA와 fragment 이동도 기록하지 않는 제한을 둔다. [설계](history-design.md)에 호출 흐름과 나머지 범위를 기록했다.

새 검사 25개를 포함한 Rust 단위 231개가 통과했다. 임시 파일과 비활성 브라우저 상태, 순수 검색 모델의 증거이며 최종 앱의 CEF, AppKit, IME와 실제 메모리 검증은 아니다. 기존 바이너리를 교체하거나 사용자 프로필을 접근하지 않았다. 실제 앱에서 기록 수집, 삭제, 재실행과 선택 보존을 확인하기 전에는 이 단계의 사용성 완료로 표시하지 않는다.

## 탭 순환과 입력 보호 보완

기존 `Ctrl+Tab`, `Ctrl+Shift+Tab`, `⌘⇧[`와 `⌘⇧]`는 현재 공간의 탭을 순환하지만, 선택 검증 전에 목록 화면을 닫고 주소 초안을 지우는 경로를 사용했다. 2026-10-15 보완은 번호 선택과 같은 검증 후 화면 전환 경로로 통합하는 소스 변경이다. 보기 메뉴에도 이전 탭과 다음 탭을 노출한다. 한 탭뿐이거나 현재 선택이 없을 때는 아무것도 바꾸지 않고, 반복 키와 입력기 조합 중에는 예약한 단축키를 소비하되 선택하지 않는다.

동작 순서는 현재 공간의 사이드바 순서이며 최근 사용 순서가 아니다. 처음과 끝은 서로 이어지고 다른 공간의 탭은 제외한다. 실제 소속이나 탭 수명이 바뀌어 선택이 거절되면 검색, 북마크, 다운로드 화면을 먼저 닫지 않는다. 성공한 선택만 기존 동기화 경로로 처리하며 소유 작업을 handoff하지 않는다. 별도 탭 목록이나 저장소를 추가하지 않고 순환마다 만들던 임시 목록을 없앤다. 전체 브라우저 메모리 절감량은 별도 측정 전까지 주장하지 않는다.

소스 검증과 실제 실행은 작업 기록에서 구분한다. 후속 네이티브 검사에서는 한 탭의 주소 초안과 세 목록 화면, 두 탭 이상의 양방향 순환과 끝 순환, 아홉 개를 넘는 탭, AI 공간별 소유권과 revision, 실제 입력기 조합, 메뉴 표시와 포커스를 확인해야 한다. 사용자 프로필과 기존 탭을 보존한 같은 최종 바이너리의 검사가 필요하며, 이전 빌드의 성공을 합산하지 않는다.

Rust 단위 206개와 전체 타깃 컴파일, 포맷 검사가 통과했다. 새 검사 3개는 순환 대상과 단축키 해석을 다루며 실제 AppKit 이벤트 실행은 아니다. 기존 앱과 CLI는 변경하지 않았고 검사 중간 파일 약 1.8GiB를 정리했다. 근거는 `artifacts/tab-cycle-v1-validation.json`과 [작업 기록](work-log.md)에 남긴다.

v2의 네이티브 종료 메뉴를 실행한 뒤 앱 세션 exit 0을 확인했고, 같은 프로필·바이너리로 재시작한 뒤 추가 승인 없이 로컬 HTTP 로딩과 화면 표시를 확인했다. 검증 탭을 닫고 기존 빈 탭 1·대기·캡처·생성 예약 0으로 돌아왔으며 빈 북마크 목록도 확인했다. 이전 앱 프로세스는 없고 검증용 HTTP 서버는 종료했다. 검사 후와 재시작 후 각 6개 프로세스의 RSS 세 표본도 기록했다. 공유 메모리 중복과 실행 조건 차이가 있어 두 시점이나 이전 v3와의 차이를 메모리 절감 효과로 판단하지 않는다. 수치와 조건은 [메모리 문서](memory.md)에 있다.

IME 조합·좁은 창·외부 사이트·장시간 사용은 남아 있다. v1은 정상 종료 exit 0으로 교체했고 빌드 중간 파일 3,537개·1.9GiB를 정리했다. 빌드·대기·재시작과 정리 기록은 `artifacts/find-page-v2-validation.json`에 있다. 키체인 대기는 해소됐고 2026-10-11 후속 조회에서 목표 도구는 `active`를 반환했다. 전체 독립 브라우저 목표는 남은 기능과 검증 때문에 미완료다. 같은 바이너리의 재실행은 확인했으며 재서명 후 무승인 실행까지 해결한 것은 아니다.

후속 입력 검사에는 저장·전송 없이 최근 이벤트 20개만 유지하는 `/ime-input.html` fixture를 추가했다. 같은 v2에서 HTTP 완료, 한글 문구 찾기 `1/1`, 205자 붙여넣기의 200자 제한, 사이드바 접기 후 찾기 값과 포커스 유지, Esc 닫기를 확인했다. CUA의 `r`·`k`는 trusted `insertText`로 각각 들어왔지만 composition 이벤트는 모두 0이었다. 실제 IME 성공이나 제품 결함으로 판정하지 않는다. 창 테두리 드래그도 크기를 바꾸지 못해 최소 크기 화면 검증은 남았다. 근거는 `artifacts/input-layout-v1-native.json`, 재현과 판정 기준은 [입력 검증 절차](input-validation.md)에 있다. 제품 코드와 승인된 바이너리는 바꾸지 않았다.

## 유지할 원칙

2026-10-13에 연속 다운로드용 네이티브 권한 UI와 최대 4개 대기, CLI 상태 개수를 추가했다. v1의 실제 CEF에서 보이는 탭의 권한 요청과 네이티브 취소를 확인했지만, 숨긴 탭의 권한 콜백은 Chromium이 공간 표시까지 보류했다. 중지 뒤 늦은 요청이 새 소유자로 나타나는 결함을 재현해 문서별 최초 요청 소유권을 고정하는 v2 보호를 추가했다. 같은 문서의 새로운 요청도 보수적으로 취소될 수 있어 제어권 변경 뒤에는 직접 새로 고침이 필요할 수 있다.

권한 v2의 Rust 174개, 전체 타깃 검사, format과 release 빌드는 통과했다. 첫 HTTP 승인 대기가 해소된 뒤 같은 바이너리의 로컬 HTTP 완료를 확인했다. 자동 검사는 처음에 paused 탭의 unscoped 접근을 잘못 전제해 `TASK_REQUIRED`로 실패했고, 해당 사례를 네이티브 검사 대상으로 분리했다. 수정한 최종 하네스는 인계, 탐색, 숨긴 요청의 adopt와 handoff 4개 사례를 통과했다. 자체 공간을 명시적으로 표시하는 검사이며 배경 자동 권한 알림이 구현됐다는 뜻은 아니다. 작업과 탭, 서버를 정리한 뒤 원래 사용자 탭 1과 다운로드 0개를 보존했다. 근거는 `artifacts/download-permission-v2-smoke-final.json`이다.

별도 네이티브 검사에서 일반 attachment 링크의 두 번째 요청이 비동기 권한 대기로 전환됐고 사용자 공간 복귀 후에도 대기를 유지했다. 최종 카드 순서, 이번 요청 취소 후 카드 제거와 닫기 버튼 포커스, 작업 종료 후 원래 탭 복귀를 확인했다. 같은 v2의 select 10개, tasks 6개, spaces 10개, single_window 6개도 모두 exit 0과 빈 stderr로 통과했다. 검사 작업 9개를 정리했고 원래 사용자 탭 1과 다운로드, 대기 요청, 캡처, 탭 생성 예약 0개를 확인했다. 근거는 `artifacts/download-permission-v2-suite.json`과 `artifacts/download-permission-v2-suite-state.json`이다.

같은 권한 v2의 후속 네이티브 검사에서 허용한 두 파일을 저장했다. 131,072바이트와 8,388,608바이트 모두 고정 fixture 원본과 일치했고 사용자 공간과 AI active revision 1은 유지됐다. 완료 기록을 지워도 파일을 보존했으며 확인 뒤 자체 검증 파일만 삭제했다. paused 탭의 사용자 요청 뒤 AI 재개에서는 권한 대기만 취소하고 먼저 접수한 사용자 파일의 저장 대기를 유지했다. 해당 작업 종료로 대기 전부 0개와 원래 사용자 탭 1로 복귀했다. 근거는 `artifacts/download-permission-v2-native-followup.json`이다. 외부 사이트와 새 모의 DOM 검사는 미실행이다. 후속 메모리 표본은 검사를 마친 user 빈 탭 하나에서 RSS 합계 722.094MiB였으며 공유 매핑 중복과 누적 검사 조건 때문에 절감량으로 판단하지 않는다. ## 페이지 확대 API 검토 — 구현 보류

페이지 확대 기능은 구현하지 않았으며 UI 초안은 되돌렸다. 설치된 CEF 156 공개 헤더의 `Zoom`·`CanZoom`·`SetZoomLevel` 계약과 현재 공식 CEF·Chromium 소스를 읽기 전용으로 검토했다. 설치 바이너리에 고정된 CEF 커밋의 구현 원문과 실제 확대 동작은 검증하지 않았으므로, 아래는 API·설계 근거이며 실행 결과가 아니다.

Naru는 탭마다 global request context를 사용한다. 공식 구현의 기본 확대는 공유 host 값에 기록되며, HTTP(S)의 키는 끝 점을 제거한 host로 scheme·port를 포함하지 않는다. 현재 열린 탭이나 요청 URL의 충돌만 막아도 이후 같은 host로 이동하는 AI 탭에 영향을 줄 수 있어, 현재 탭 목록만 검사하는 방어로는 작업 격리를 보장할 수 없다. [CEF 확대 호출 경로](https://github.com/chromiumembedded/cef/blob/master/libcef/browser/browser_host_base.cc), [Chromium 확대 처리](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/components/zoom/zoom_controller.cc), [host 키 생성](https://chromium.googlesource.com/chromium/src/+/main/net/base/url_util.cc).

Chromium 내부에는 탭별 temporary/isolated 확대가 있지만 설치된 CEF 공개 API에는 모드 설정이 없고, 내부 격리 모드도 문서 탐색 시 초기화된다. Chromium은 host 확대값의 프로필 저장·복원 경로도 갖지만 Naru의 재시작 보존은 미검증이다. 후속 구현은 엔진과 호스트의 경계에서 탭별 확대·탐색·기본값 복원·저장 정책을 설계하고, 다른 AI 탭에 영향이 없음을 검증한 뒤 진행한다. [격리 모드와 탐색 처리](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/components/zoom/zoom_controller.cc), [확대값 저장·복원](https://chromium.googlesource.com/chromium/src/+/lkgr/chrome/browser/ui/zoom/chrome_zoom_level_prefs.cc).

## 2026-10-18, 하위 프레임 연결을 위한 명령 전송 정리

기존 명령 다섯 경로를 raw DevTools 전송으로 통합하고 응답을 소비하기 전에 루트 연결과 원 Browser를 대조한다. 미리보기와 screenshot의 늦은 응답도 같은 경계를 따르며 ID를 재사용하지 않는다. 이 단계에서는 child session 연결과 frame-local 읽기·입력이 후속 범위였으며, 이후 메타데이터 수집과 위 단일 프레임 내용 조회를 소스에 연결했다. [연결 설계](devtools-routing.md)의 전송 경계와 실제 앱 검증을 구분한다. 교차 출처 iframe 지원 완료나 실제 앱 통과는 아니다. 전체 회귀 묶음은 반복하지 않고 최종 사용 여정의 E2E에서 기존 입력, 캡처와 프레임을 이어서 확인한다.

## 2026-10-18, 현재 탭의 프레임 연결과 메타데이터 조회

`frames TAB`과 작업 범위의 같은 명령을 구현했다. 현재 탭의 루트와 iframe child session에 Page.enable, 제한된 autoAttach, getFrameTree를 연결하며 원 Browser·정확한 session·요청 ID를 확인한다. root ACK만으로 재귀 수집이 끝났다고 판단하지 않는다. 16개 자식 연결·깊이 8과 전체 128개 메타데이터 행 예산을 적용했다. 중복 frame ID, 수집 중 탐색·프레임 변경과 제어권 변경은 실패로 처리하며 자동 재시도하지 않는다.

`frames` 결과는 비원자적 메타데이터이며 본문이나 조작 가능한 ref가 아니다. 후속 `read-frame`의 단일 문서 내용 조회와 context identity는 위 기록처럼 소스에 연결했으며, 이후 action ref와 7개 입력, 부모 좌표와 포인터 hit-test도 연결했다. 후속 read-page는 여러 프레임 본문을 공통 예산으로 읽는다. 지원 밖 변환은 남아 있다. 실제 OOPIF 연결과 해제, 사용자 선택 보존, 취소와 누적 자원은 [통합 E2E 08·14](ego-parity-e2e.md)에서 같은 최종 바이너리로 확인해야 한다. 전체 회귀 묶음을 실행하지 않았으며 새 프로세스나 UI 렌더러 없이 기존 CEF 연결을 이용한다.
