# 현재 주소를 내 공간 새 탭에서 열기

파일 메뉴의 `현재 주소를 내 공간 새 탭에서 열기`는 표시 중인 웹페이지의 주소를 새 사용자 탭에서 여는 기능이다. AI가 사용 중인 페이지도 원본 작업을 중지하거나 탭의 소유권을 옮기지 않고 내 공간에서 따로 열 수 있게 한다. 같은 주소의 사용자 탭이 이미 있어도 새 탭을 만든다.

## 동작 계약

메뉴는 현재 보이는 탭을 대상으로 한다. 공간 목록, 검색, 북마크, 다운로드 화면이나 입력기 조합 중에는 실행하지 않는다. 빈 탭, 내부 페이지, 자격증명이 포함된 주소와 지원하지 않는 주소도 제외한다. 단축키를 새로 추가하지 않는다.

주소창에 편집 중인 문자열을 읽지 않는다. 탭의 공간, 선택, 탐색 세대와 준비 상태를 확인한 뒤 CEF의 실제 main frame 주소를 읽는다. 기존 HTTP(S) 주소 정규화와 길이 제한을 적용하고, UI가 가리킨 주소와 같은지 확인한다. CEF 조회나 생성 콜백 중 원본 탭 또는 제어권이 바뀌면 오래된 요청으로 선택을 바꾸지 않는다.

새 탭은 AI 소유권이 없는 내 공간의 탭으로 만든다. 창 연결과 원본 재검증이 끝날 때까지 배경에 두고, 성공한 경우에만 내 공간의 새 탭을 선택한다. 원본 AI 공간의 선택 탭과 작업 revision은 유지한다. 생성 또는 재검증 실패는 기존 주소 초안과 편집기를 지우는 일반 탐색 경로로 처리하지 않는다. 실패 후 정리가 필요하면 이번 동작이 만든, 아직 AI가 소유하지 않은 사용자 탭만 대상으로 한다.

이는 주소를 새로 탐색하는 기능이다. 폼 입력, 스크롤 위치, 뒤로가기 목록, POST 요청 본문과 문서 상태를 복제하지 않는다. 모든 공간은 기존 브라우저 프로필과 쿠키를 공유하며 별도 로그인이나 보안 경계를 만드는 기능이 아니다.

## 코드와 자원

`src/control_panel.rs`의 네이티브 메뉴가 현재 화면의 대상을 만들고 `src/browser.rs`가 실제 상태와 주소를 검증한다. 탭 생성과 성공 후 선택에는 기존 CEF, AppKit 경로를 사용한다. CLI 계약은 유지한다.

새 저장소, 상주 타이머, 페이지 캡처나 본문 캐시를 추가하지 않는다. 명시적인 메뉴 실행마다 웹 탭 하나를 추가하므로 Chromium의 페이지 자원은 늘 수 있다. 생성 실패와 뒤늦은 무효화는 기존 탭 종료 경로로 회수하며 원래 탭이나 사용자 프로필을 삭제하지 않는다.

## 검증 범위

이 문서의 동작 계약은 실제 앱에서 확인한 결과와 구분한다. 소스와 상태 검사 결과는 [작업 기록](work-log.md)에 남긴다. 현재 보존 중인 numbered-tabs-v3 앱에는 이 기능이 포함돼 있지 않다.

2026-10-15 소스는 Rust 단위 검사 203개, 전체 타깃 컴파일 검사, 포맷 검사를 통과했다. 새 검사 4개는 UI의 현재 대상 선택, 숨은 화면과 지원하지 않는 주소 거절, 실제 주소와 대상의 일치, 런타임 상태 가드를 다룬다. 런타임 검사는 오래된 대상과 제어권, UI 변경 거절, 배경 탭 삽입 시 원래 선택 보존, 정리 대상의 자격, 실제 사용자 탭 선택 함수의 AI 상태 보존을 확인했다. CEF를 초기화하거나 AppKit 화면에서 실행한 검사가 아니다. 근거는 `artifacts/current-page-v1-validation.json`과 해당 검사 로그다.

후속 네이티브 검사는 사용자 공간과 AI 공간에서 각각 메뉴를 실행해 새 탭의 주소, 소유권, 선택을 확인해야 한다. 다른 AI 작업의 revision, 원본 공간의 선택, 주소 초안 보존도 함께 확인한다. 공간 목록과 각 목록 화면, 입력기 조합, 페이지 이동, 생성 실패와 창 연결 실패, 생성 중 원본 변경과 새 탭의 소유권 변경도 실행 경로로 검증해야 한다. 반복 실행 후 만든 탭만 닫고 자원 회수와 메모리를 측정한다. 이 항목들은 아직 실행 결과가 아니다.
