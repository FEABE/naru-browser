# 재시작 탭 복원 설계 초안

2026-10-15, 사용자가 탭 복원 보류를 선택했다. 아래는 채택하지 않은 검토안이며 저장소나 복원 코드는 구현하지 않는다. 이 문서는 구현 완료나 사용자 데이터 수집을 뜻하지 않는다. 현재 앱은 시작할 때 빈 사용자 탭을 생성하고 마지막 CEF 탭이 닫히면 종료한다. 북마크와 방문 기록은 별도로 저장하지만 열린 탭 목록은 저장하지 않는다.

## 제안하는 사용자 정책

기존 Naru 데이터 폴더의 별도 `session-v1.json`에 내 공간의 소유되지 않은 탭만 저장한다. HTTP(S) URL, 표시 제목, 순서와 선택 위치가 대상이다. URL은 기존 정규화와 자격 증명 제외 정책을 따르며 폼, 본문, 뒤로 가기 이력, 주소 입력 초안, AI 작업 ID나 revision은 저장하지 않는다. 쿠키와 로그인은 기존 Chromium 프로필의 책임이며 이 JSON으로 복원하지 않는다.

상한 제안은 사용자 탭 16개, 파일 256KiB다. 상한을 넘으면 선택한 탭을 우선 포함하고 남은 탭은 현재 표시 순서로 포함하며 일부만 보관됐음을 알린다. 빈 시작 탭의 보관 여부는 아직 결정하지 않았다. 파일은 최신 상태 한 개만 유지하고 과거 목록 백업은 만들지 않는다. 손상 파일을 임의로 덮어쓰거나 백업에서 자동 승격하지 않는다.

시작 시 선택한 탭 한 개만 Chromium으로 만들고 나머지는 제목과 URL이 있는 대기 탭으로 표시하는 방식을 권장한다. 사용자가 선택한 대기 탭만 실제 페이지를 생성한다. 모두 즉시 생성하는 복원은 renderer와 네트워크 사용이 한꺼번에 늘어 사용자의 메모리 우선 방침에 맞지 않는다. 대안은 자동 탐색 없이 이전 목록만 보여 주고 사용자가 선택할 때 여는 방식이다.

복원하지 않고 새로 시작하는 선택과 보관 목록 전체 삭제도 함께 제공해야 한다. 삭제 뒤 늦은 저장이 이전 목록을 되살리지 않도록 세대 경계를 둔다. 정상 종료 때 닫힘 콜백이 목록을 비워 버리지 않도록 종료 요청 직전의 사용자 목록과 개별 탭 닫힘을 구분한다. 종료 중 일부 페이지가 beforeunload를 취소하면 남은 살아 있는 상태를 기준으로 이후 저장을 재개한다. 강제 종료는 마지막 성공한 저장 지점까지 복구하며 최신 상태 보장을 주장하지 않는다.

## 현재 코드에서 확인한 경계

`main`은 CEF 초기화 후 북마크와 방문 기록 런타임을 열고 메시지 루프 종료 뒤 파일 작업을 정리한다. `browser`의 탭 ID는 CEF browser ID이며 `Spaces`, ShellTab, CLI와 작업 소유권이 이 ID를 사용한다. 대기 탭을 가짜 CEF ID로 끼워 넣으면 CLI 명령과 실제 host 수명이 혼동된다. 화면 탭 식별자와 실제 CEF 핸들의 연결을 분리하거나 대기 복원 항목의 별도 타입을 사용하고, 생성 성공 시 명시적으로 연결해야 한다.

`close_all`은 명시적 창 닫기와 앱 종료에서 호출되고 마지막 탭의 do_close는 네이티브 창을 해제한다. OnBeforeClose는 탭이 없으면 메시지 루프를 종료한다. 따라서 탭 없는 네이티브 창과 종료 요청의 구분이 탭 복원에 앞선 수명주기 과제다. AI finish가 마지막 탭을 닫아도 CLI 연결을 계속 제공하는 경계를 함께 검토한다.

북마크는 사용자가 보관한 항목이고 방문 기록은 30일 동안 방문한 URL 집합이다. 동일 URL의 여러 탭과 현재 순서, 선택을 표현하는 세션 목록을 이 두 저장소에 혼합하지 않는다. 저장 방식과 범위는 별도 사용자 선택을 받기 전 구현하지 않는다.

## 구현과 검증 순서

1. 탭 닫기와 창, 앱 종료의 수명주기를 분리하고 취소와 생성 경합을 검증한다.
2. 사용자가 저장 범위와 시작 방식을 선택한 뒤 파일 스키마와 저장, 삭제, 손상 처리를 구현한다.
3. 실제 CEF ID와 혼동되지 않는 대기 탭을 연결하고 선택 시에만 생성한다. 생성 실패는 원래 항목을 유지하며 다른 사용자 선택을 되돌리지 않는다.
4. 정상 재시작, 중간 종료, 선택 변경과 로드 경합, 중복 URL, AI 제외, 상한과 삭제를 검증한다.
5. 같은 최종 앱에서 네이티브 UI, 실제 HTTP, 로그인 유지와 장시간 메모리를 확인한다. 소스와 단위 검사만으로 이 단계의 통과를 선언하지 않는다.

앱 생성과 서명, 실행, CEF 초기화와 키체인 접근은 이번 설계에서 하지 않는다. Preseller에 내장할 때는 저장 위치와 창 종료의 최종 책임을 호스트가 제공하되 같은 탭과 공간 모델을 사용해야 한다.

## 보류 후 확인한 종료 제약

기존 기본 beforeunload 대화상자의 취소 결과를 공개 CEF 콜백으로 구분할 수 없다. CEF `javascript_dialog_manager.cc`는 OnBeforeUnloadDialog가 false를 반환해 기본 대화상자로 넘기면 handler 연결을 제거하고, OnDialogClosed도 handler가 있는 경우만 전달한다. TryCloseBrowser의 false도 대기와 취소를 구분하지 못한다. 따라서 종료 플래그 하나를 추가하고 새 탭 생성을 막으면 취소 뒤 앱을 잠그거나 나중에 다른 닫힘에서 종료할 수 있다. 이 방식은 적용하지 않았다.

근거는 고정 CEF 커밋의 [기본 대화상자 전달](https://github.com/chromiumembedded/cef/blob/8db2f36735f06aacaf1bab832cb08da9d9445c55/libcef/browser/javascript_dialog_manager.cc#L200), [종료 알림](https://github.com/chromiumembedded/cef/blob/8db2f36735f06aacaf1bab832cb08da9d9445c55/libcef/browser/javascript_dialog_manager.cc#L308), [beforeunload 취소 처리](https://github.com/chromiumembedded/cef/blob/8db2f36735f06aacaf1bab832cb08da9d9445c55/libcef/browser/alloy/alloy_browser_host_impl.cc#L952)다. 탭 없는 창 UI는 이미 있으나 마지막 탭과 앱 종료를 분리하려면 취소 결과를 직접 받는 대화상자 또는 명시적인 종료 요청 수명 정책부터 설계해야 한다. 현재 종료 동작은 바꾸지 않았다.

저장 후보의 URL은 `Navigation.requested_url`로 대체하면 안 된다. 다운로드가 되는 임시 목적지도 포함하기 때문이다. 복원을 재개할 때는 실제 main-frame 주소와 commit된 문서를 기준으로 보관할 URL을 정해야 한다.
