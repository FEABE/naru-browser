# 최근 닫은 사용자 탭 다시 열기

기준일: 2026-10-11. 일상 탐색 중 실수로 닫은 웹 주소를 다시 여는 기능이다. `파일 → 최근 닫은 탭 다시 열기` 또는 `⌘⇧T`를 사용한다. v1의 로컬 네이티브 검사에서 기본 복구는 확인했으나, AI 공간의 단축키가 작업을 중지시키는 결함을 발견했다. v2는 Rust 144개와 로컬 CEF 회귀 22개를 통과했고, 네이티브 입력에서 AI 상태 보존·본문 키 차단·사용자 탭 복원을 확인했다.

## 동작 계약과 범위

- 현재 앱 실행 동안 실제로 닫힌 사용자 공간의 HTTP(S) 주소를 최대 10개 기억한다. 가장 최근 주소부터 새 사용자 탭으로 연다. 같은 URL이어도 각각 닫힌 탭을 별도 항목으로 취급한다.
- 종료 요청만으로 기록하지 않는다. CEF의 `on_before_close`에서 실제 종료를 확인한 뒤 기록하므로 beforeunload 취소로 살아 있는 탭은 추가하지 않는다. 이때 아직 유효한 main frame에서 주소를 읽으며 미완료 탐색의 요청 주소나 주소창 초안을 저장하지 않는다.
- 기록 시점에 사용자 공간이고 AI 소유권이 없는 탭만 대상이다. paused 작업, AI 작업 결과 공간, borrowed 탭은 제외한다. CLI가 사용자 탭을 닫은 경우도 포함하며 클릭 출처를 구분하는 기능은 아니다.
- 사용자 공간에서만 실행한다. AI 공간, 모든 공간 화면, 통합 검색·북마크 화면, 현재 입력기의 조합 중에는 메뉴를 비활성화하고 단축키로도 탭을 만들거나 화면을 닫지 않는다. 빈 사용자 공간도 대상이며 다른 AI 작업을 중지하지 않는 것이 계약이다. v1의 AI 공간 단축키는 이 계약을 어겼으며 아래 수정·검증 범위를 따른다.
- 생성과 창 연결이 성공한 항목만 목록에서 제거한다. 실패하면 재시도할 수 있고 주소 초안을 버리지 않는다. 생성 중 재진입은 막고, 다른 탭이 동시에 닫혀도 완료한 항목의 token만 제거한다.
- URL을 새로 탐색한다. 페이지의 폼 입력, 스크롤 위치, 뒤로가기 목록이나 문서 상태는 복원하지 않는다. 앱을 완전히 종료하면 기록은 사라진다. 마지막 탭을 닫아 앱이 끝나는 기존 동작도 유지한다. 앱 종료를 일부 탭이 취소해 앱이 남아 있으면 실제로 닫힌 사용자 탭의 주소는 다시 열 수 있다.

## 자원과 코드 경계

`src/closed_pages.rs`는 URL과 token만 보관한다. 주소당 최대 8,192바이트, 기억하는 URL payload는 최대 80KiB다. 진행 중 생성에는 URL 사본 하나가 필요하며 문자열·컨테이너 overhead와 정규화 임시 할당은 별도다. Browser, Frame, 렌더러, 화면 캡처, 페이지 본문·제목을 보관하지 않는다. 파일·DB·worker·타이머를 추가하지 않으며 실제 Chromium 전체 메모리 사용량이 이 크기로 제한된다는 뜻은 아니다.

기존 `address::normalize_url`로 HTTP(S)·주소 형식·최종 인코딩 길이를 확인한다. 자격증명이 포함된 주소, about:blank, file/data/javascript 주소는 기억하지 않는다. 지원하지 않는 주소를 검색어로 바꿔 열지 않는다.

`src/browser.rs`는 종료 당시 공간·소유권을 확인하고 기존 탭 생성·선택 경로로 새 사용자 탭을 만든다. `src/control_panel.rs`의 메뉴 validation과 실행 시 guard는 같은 조건을 사용한다. 단축키는 기존 새 탭과 검색 화면 닫기 분기보다 먼저 처리한다. 이 기능에는 별도 CLI 명령을 추가하지 않는다.

## v1에서 확인한 로컬 네이티브 동작

검증 바이너리 SHA-256은 `98dc57f68fd90783e86eafa832d05830e74311c77bb1fec4fa81e24f2ba25402`다. 사용자 키체인 승인 뒤 같은 바이너리에서 탭 2의 로컬 HTTP load 완료를 확인했다. 근거는 [reopen-v1-native.json](../artifacts/reopen-v1-native.json)이며 아래 내용은 해당 실행의 결과다.

- URL B의 탭 3을 네이티브 UI로 닫고 URL A의 탭 2를 CLI로 닫았다. 파일 메뉴로 A가 새 사용자 탭 4에 열렸고, 이어 `⌘⇧T`로 B가 새 사용자 탭 5에 열려 역순 복구를 확인했다. 목록을 모두 소비한 뒤에는 단축키로 새 탭이 생기지 않고 메뉴가 비활성화됐다.
- A에서 페이지 찾기 `needle`의 `1/8` 결과를 표시한 상태로 B를 복구하자 찾기 UI가 닫혔다. 이어 `⌘G`를 눌러도 이전 검색이 되살아나지 않았다.
- 로컬 beforeunload 경고가 실제 표시된 뒤 Cancel을 선택하자 탭 6이 살아 있었고 복구 목록도 비어 있었다. 이후 경고에서 OK로 닫은 뒤에는 같은 URL을 탭 7로 다시 열었다.
- borrowed 탭 4는 네이티브 닫기로 작업이 revision 1→2, paused가 된 뒤 종료됐으며 복구 목록에서 제외됐다. 작업이 만든 탭 8의 scoped close도 제외됐다. `--keep`으로 남긴 탭 9는 소유권이 해제됐어도 완료된 AI 작업 공간에 있었으므로 닫은 뒤 복구 대상이 되지 않았다.
- 복구할 항목이 남은 상태에서 통합 검색·북마크 화면의 검색어 `검증`과 입력 포커스가 단축키 뒤에도 유지됐다. 모든 공간 화면에서도 새 탭이나 화면 전환이 발생하지 않았다.

## 발견한 결함과 수정 소스

v1에서 활성 AI 작업의 revision 3, 탭 9를 표시하고 `⌘⇧T`를 누르자 새 탭은 생성되지 않았지만 작업이 revision 4, paused로 바뀌었다. 따라서 v1에 대해 AI 제어권 보존 검사가 통과했다고 할 수 없다.

같은 v1의 진단용 사용자 페이지도 trusted `keydown`을 받았다. 기록된 값은 `code=KeyT`, `meta=true`, `shift=true`, `control=false`, `alt=false`, `latin=true`, `hangul=false`다. 사용자 공간에서는 본문에 키가 전달된 뒤 메뉴 경로로 복구됐다. AppKit의 `charactersIgnoringModifiers` 값 자체는 수집하지 않았으므로, 정확한 문자 변환 원인이나 CEF 전달 경로까지 확정한 증거는 아니다. 진단 fixture는 알려진 조합의 Boolean 값과 최근 20개 이벤트만 보관한다.

수정 소스의 `control_panel::is_reopen_event`는 실제 Command·Shift 조합과 Option·Control 제외를 먼저 검사한 뒤 `charactersByApplyingModifiers(Command | Shift)`로 현재 입력 소스에서 문자를 재번역한다. 유효하지 않은 이벤트로 재번역 값이 없으면 기존 문자 조회로 보완한다. 이 판정을 일반 문자 조회보다 먼저 실행하고, 인식한 단축키는 비활성·반복 입력도 소비한다. 하드코딩한 물리 키코드나 한글 문자 매핑은 추가하지 않았다.

[reopen-v2-rust-tests.log](../artifacts/reopen-v2-rust-tests.log)에서 Rust 144개 검사 통과를 확인했다. 최근 10개·역순 복구, URL 거절 시 기존 항목 보존, 생성 실패 후 재시도, 중복 요청 차단, 재진입 중 정확한 token 소비와 오래된 완료 무시를 포함한 상태 검사다. 실제 AppKit 문자 재번역, CEF 키 전달 및 새 바이너리의 결함 해결을 증명하지는 않는다.

로컬 NSEvent 객체 검사에서 SDK의 ANSI T와 unmodified 문자 `t`·`T`·`ㅆ` 세 조건을 구성했다. 새 API 재번역은 모두 T를 반환했고 기존 문자열 판정은 `ㅆ`를 인식하지 못했다. 이벤트 전송·입력 소스 변경은 없었다. 원본은 `artifacts/reopen-v2-key-translation.json`이며 실제 v1 원인 확정이나 수정 앱의 네이티브 검증을 대신하지 않는다.

## v2 실제 검증과 남은 범위

검증한 v2 SHA-256은 `84bfaf36d80d6b6048461b07fcbef5c5bca2862c3408aa7d2e772e1fa5204100`다. 첫 HTTP 탐색 대기가 해소된 뒤 같은 바이너리에서 사용자 입력란에 포커스를 두고 ⌘⇧T를 보냈다. 빈 목록에서는 새 탭과 DOM keydown·keyup이 없었다. AI 공간에서는 닫힌 사용자 URL 기록 유무와 관계없이 active·revision 1을 유지했다. 실제 입력란 클릭은 정상적으로 paused·revision 2를 만들었고 재개 후 단축키는 active·revision 3과 DOM keydown·keyup 0을 유지했다. 재개와 단축키 사이에 클릭하지 않았다.

B4 다음 A3을 닫은 뒤 사용자 공간에서 단축키가 A5를, 파일 메뉴가 B6을 만들었다. 각각 task 소유권 없는 새 사용자 탭이었다. A의 needle 1/8 찾기는 B 복원 때 닫혔고 ⌘G로 되살아나지 않았다. v1에서 확인한 beforeunload·AI 탭 제외·overlay 검사는 이번 v2에서 전부 반복하지 않았으며 위의 v1 근거와 구분한다.

로컬 CEF 회귀 tasks 6개·spaces 10개·single_window 6개, 총 22개가 모두 통과했다. 각 exit 0·stderr 0바이트였고 검증 작업 7개와 소유 탭을 정리했다. 원래 사용자 탭 1과 pendingWaits·capturesInFlight·pendingTabCreations 0을 확인했다. 근거는 `artifacts/reopen-v2-suite.json`과 `artifacts/reopen-v2-suite-state.json`이다. 이 cleanup 결과만으로 최근 닫기 목록이 비었다고 해석하지 않는다.

이후 네이티브 종료 메뉴로 exit 0을 확인하고 같은 바이너리를 재실행했다. 복원 메뉴는 비활성화됐고 ⌘⇧T도 원래 빈 탭 하나를 유지했다. 별도 검증 작업에서 HTTP를 다시 로드하고 정리했으며 원래 사용자 탭은 유지했다. 이전 앱과 fixture 서버는 종료했다. 네이티브 원본은 `artifacts/reopen-v2-native.json`, 재실행 HTTP·정리는 `artifacts/reopen-v2-restart.json`, 종합 기록은 `artifacts/reopen-v2-validation.json`에 있다.

실제 생성 실패, 미완료 탐색 중 닫기의 주소 선택, 앱 종료 일부 취소, 실제 IME 조합, 외부 사이트와 장시간 반복은 아직 검증하지 않았다. 재서명 후 키체인 승인 요청을 없앤 결과도 아니다. [작업 기록](work-log.md)에 소스 검사와 로컬 앱 검사, 남은 제한을 구분해 기록한다.
