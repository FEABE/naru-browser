# Aside와 ego lite 실제 앱 비교

기준일: 2026-10-11. 설치 앱의 표시 버전은 Aside `1.0.928.1`, ego lite `0.5.1.13`이다(각 앱의 Info.plist 확인).

설치된 macOS 앱을 네이티브 CUA로 조작한 기록을 비교했다. ego lite의 외부 에이전트 제어는 별도 CLI 작업 공간에서 확인했다. 웹사이트 소개나 시연 영상의 기능을 실제 실행 결과로 계산하지 않았다. Naru 소스, 빌드, 앱 실행은 이 비교 문서 작성 범위에 포함하지 않는다.

## 일상 브라우저 사용

| 확인한 흐름 | ego lite | Aside |
| --- | --- | --- |
| 새 탭과 공간 | 새 사용자 공간에 탭 두 개를 만들었다. 마지막 검증 탭을 닫자 해당 공간이 사라지고 최초 두 공간으로 돌아왔다. | 새 탭 중앙에 Search와 Ask 선택, 입력란이 표시됐다. 중앙 입력란에 포커스가 있어 바로 입력을 시작할 수 있었다. |
| 세로 탭 | 세로 탭 영역을 접고 다시 펼쳤다. | 사이드바에서 Bookmarks, Chats, Tabs를 구분해 표시했다. 접기와 펼치기를 실행하고 처음의 펼친 상태로 복원했다. |
| 웹 검색 | 주소 입력으로 검색한 뒤 Google 결과 페이지가 열렸다. | 중앙 검색에서 Google로 요청한 뒤 `/sorry`로 이동했다. 검색 요청은 확인했지만 결과 페이지를 이용하는 흐름은 검증하지 못했다. |
| 북마크 | 이름을 수정해 저장하고 다시 열었다. 직접 만든 검증 북마크는 삭제했다. | ⌘D로 이름을 수정하고 북마크 바 위치를 선택하자 사이드바에 링크가 생겼다. 링크를 누르면 기존 검증 페이지의 입력값과 클릭 횟수 1이 유지됐다. 열린 탭을 다시 선택하는 동작을 관찰했다. |
| 북마크 이름 | 이름을 수정하고 다시 여는 흐름을 확인했다. 표시 위치별 이름 차이는 비교하지 않았다. | 열린 북마크의 사이드바 표시는 페이지 제목으로 바뀌었지만, Bookmarks 검색 결과에는 저장할 때 정한 이름이 유지됐다. |
| 통합 검색 | 이번 비교에서는 검증하지 않았다. | Search 버튼으로 검색 창을 열었다. 입력 안내에는 탭, 채팅, 기록, 북마크, 확장 검색이 표시됐다. `Naru` 검색에서 Open Tabs, Bookmarks, History 각각의 결과를 확인했다. 채팅과 확장 결과는 검증하지 않았다. |

Aside의 Google `/sorry` 이동만으로 앱 결함이라고 판단할 수 없다. 두 앱의 요청 조건을 통제하거나 원인을 분리하지 않았으므로 검색 품질 비교의 근거로 쓰지 않는다.

## 사람과 AI의 공동 사용

| 확인한 흐름 | ego lite | Aside |
| --- | --- | --- |
| AI 작업 시작 | CLI로 TaskSpace 8을 만들었다. 기존 사용자 공간의 선택을 유지했고 공간 목록에는 별도 작업 카드가 나타났다. | 현재 페이지에서 Ask Aside를 열자 오른쪽 패널과 현재 탭을 가리키는 context chip이 나타났다. |
| 작업 표시 | 작업 카드의 Running 표시와 푸른 테두리, `Agent is in control`, `Take over`, `Stop` UI를 관찰했다. | 실제 AI 작업이 진행되는 패널을 확인했다. 완료 뒤에는 작업 시간으로 15초가 표시됐다. |
| 실제 페이지 제어 | 자체 로컬 검증 페이지에서 CLI로 클릭 한 번과 입력 한 번을 실행했다. 페이지가 기록한 `clicks=1`, `inputEvents=1`, `trusted=true`를 확인했다. | 범위를 제한한 로컬 검증 요청으로 AI가 클릭 한 번과 입력 한 번을 실행했다. 페이지의 `clicks=1`, `inputEvents=1`, `isTrusted=true`를 확인했다. |
| 중지 | Take over와 Stop 버튼의 표시는 확인했다. 실제 실행은 아직 하지 않았다. | 같은 검증 페이지를 대상으로 별도 반복 요청을 보내고 즉시 Stop을 눌렀다. `Interrupted`, `Worked 0s`가 표시됐고 실행 중 버튼이 사라졌다. 다른 앱 검사 후 재확인해도 페이지 값은 클릭 1회·입력 1회였다. 진행 중인 클릭의 취소 검사는 아니다. |
| 미검증 제어권 경계 | 사용자 본문 입력에 따른 자동 인계, Take over 실행, Stop 이후 지연 명령 처리는 확인하지 않았다. | 사용자 본문 입력에 따른 자동 인계와 중지 이후 지연 명령 취소는 확인하지 않았다. |

로컬 페이지의 이벤트 기록은 해당 클릭과 입력이 실제로 전달됐다는 근거다. 모든 웹사이트의 호환성이나 사용자와 AI가 동시에 조작할 때의 안전성을 입증하지는 않는다. Aside의 15초와 0초는 화면에 표시된 값이며 반복 측정한 성능 수치가 아니다. 중지 UI가 바뀐 사실만으로 이미 전달된 조작이 취소되거나 되돌아갔다고 판단하지 않는다.

## Naru에 적용할 방향

일상 탐색은 Aside의 새 탭 입력, 북마크, 통합 검색 흐름을 참고한다. AI 협업은 ego lite에서 확인한 별도 공간, 사용자 선택 유지, 제어권 표시, CLI 작업 흐름을 기준으로 삼는다. 기존 Naru 공간 모델과 단일 창, 네이티브 AppKit UI를 유지한다.

| 다음 개발 범위 | 이번 관찰에서 얻은 근거 | Naru에서 확인해야 할 결과 |
| --- | --- | --- |
| 북마크 | 두 앱에서 저장 이름 수정과 다시 열기를 실행했다. Aside에서는 열린 페이지 상태가 유지됐고 저장 이름으로 검색할 수 있었다. | 추가, 이름 수정, 열기, 삭제와 재실행 보존을 확인한다. 저장 이름과 현재 페이지 제목을 구분하고, 이미 열린 탭을 다시 사용할지 동작을 명확히 정한다. 영속 저장 방식은 구현 전에 결정한다. |
| 통합 검색 | Aside 한 검색 창에서 열린 탭, 북마크, 기록 결과를 구분했다. | 검색 창에서 결과 종류를 식별하고 키보드로 선택한다. 탭 결과는 기존 탭으로 이동하고, 북마크와 기록은 정한 열기 정책을 따른다. 웹 검색어와 브라우저 내부 결과도 구분한다. |
| 바로 입력할 수 있는 새 탭 | Aside 새 탭의 중앙 입력란에 초기 포커스가 있었다. | 새 탭을 만든 직후 추가 클릭 없이 주소나 검색어를 입력한다. 빈 입력은 탐색하지 않고, 기존 탭으로 돌아올 때 편집 상태와 포커스를 확인한다. |
| 세로 탭과 공간 전환 | ego lite에서 사이드바 접기와 복원, AI 작업 시작 후 사용자 공간 선택 유지를 확인했다. | 현재 공간의 탭 선택, 추가, 닫기와 접기를 쉽게 식별한다. 배경 작업이나 배경 탭 생성이 사용자의 공간과 선택을 바꾸지 않는지 확인한다. |

이 흐름은 AppKit 컨트롤로 구현하며 UI용 웹 렌더러를 추가하지 않는다. 검색 패널이나 새 탭 화면 때문에 상주 렌더러, 반복 캡처, 불필요한 탭을 늘리지 않는다. 내장 대화 패널과 모델 연결은 현재 사용자가 선택한 세로 탭, 검색, 북마크 다음 단계에서 검토한다.

공간은 탭 표시와 선택을 나누는 단위다. 이 비교에서 계정별 프로필이나 쿠키 격리를 검증하지 않았으므로 보안 경계로 설명하지 않는다. 제품 전체 진행 상태는 [개발 계획](product-plan.md), Naru 완성 후 같은 구현을 Preseller에 내장하는 단계는 [내장 계획](preseller-integration.md)에서 추적한다.

## 검증 범위와 남은 확인

- **네이티브 UI:** 위 표에 기록한 설치 앱의 입력, 선택, 북마크, 공간, 패널 동작을 접근성 트리와 화면으로 확인했다. 전체 접근성 품질, 다크 모드, 모든 창 크기의 배치는 검증하지 않았다. ego lite의 접근성 트리에는 숨은 공간의 내용도 함께 노출됐고 공간 카드의 버튼 이름은 반복돼, 활성 공간 판별에는 화면 확인도 필요했다. Aside 검색의 키보드 선택으로 로컬 페이지를 열었지만 기존 탭 재사용까지는 확인하지 않았다.
- **로컬 페이지 제어:** 자체 검증 페이지의 클릭과 입력 기록을 확인했다. Aside와 ego lite에서 사용한 제어 경로가 다르므로 같은 구현이나 동등한 취소 보장을 갖는다고 해석하지 않는다.
- **외부 사이트:** ego lite는 Google 결과 페이지를 확인했다. Aside는 Google 요청 후 `/sorry` 이동까지 확인했다. 로그인 서비스, 결제, 파일 처리, 복잡한 iframe 동작은 이번 비교에 포함하지 않았다.
- **자원 사용:** 같은 페이지, 탭 수, 작업, 측정 시점으로 메모리를 비교하지 않았다. 어느 앱이 더 가볍거나 빠르다는 결론은 내리지 않는다.
- **Naru 검증:** 비교에 앞서 작성한 Naru 소스는 별도로 단위 검사 102개가 통과했다. release 빌드와 새 소스의 네이티브 실행은 하지 않았다. 자세한 변경과 상태는 작업 기록에 있으며 비교 앱의 성공을 Naru의 구현 완료 증거로 옮기지 않는다.
- **정리:** ego lite의 임시 북마크와 사용자 검증 공간을 정리했다. CLI TaskSpace 8은 `finish({keep: []})` 한 번으로 종료하고 최초 두 공간만 남은 상태를 확인했다. Aside의 임시 북마크와 검증 탭 세 개를 닫았다. 기존 New Tab과 도중에 열린 확장 온보딩 탭은 보존했다. Aside에 비교 결과를 확인할 수 있는 대화 `브라우저 UI clicks 및 inputEvents 검증` 한 개가 남아 있다. 로컬 HTTP 서버도 종료했다. 새 Naru 앱이나 추가 상주 프로세스는 실행하지 않았다.

비교 앱의 일부 흐름을 확인한 것으로 Naru 전체 목표를 완료 처리하지 않는다.
